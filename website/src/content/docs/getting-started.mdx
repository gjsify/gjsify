Install the CLI, scaffold a project, run it: that is a GTK 4 window on screen
running your own TypeScript, in about a minute. You need GNOME's `gjs` 1.86 or
newer plus GTK 4 and libadwaita on the machine; the CLI brings everything else
with it. If a step fails, jump to [If it did not start](#if-it-did-not-start).

## Install the CLI

<CommandTabs title="Install the gjsify CLI">
  <Fragment slot="gjsify">
    ```bash
    curl -fsSL https://github.com/gjsify/gjsify/releases/latest/download/install.mjs \
      -o /tmp/g.mjs && gjs -m /tmp/g.mjs && rm /tmp/g.mjs
    ```
  </Fragment>
  <Fragment slot="npm">
    ```bash
    npm install -g @gjsify/cli
    ```
  </Fragment>
  <Fragment slot="bun">
    ```bash
    bun add -g @gjsify/cli
    ```
  </Fragment>
</CommandTabs>

The **GJS** tab needs no Node.js at all: the bootstrap runs on stock `gjs`, puts
the CLI under `~/.local/share/gjsify/global/` and writes a launcher to
`~/.local/bin/gjsify`. If that directory is not on your `PATH` yet:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Updating, pinning a version and uninstalling are on the
[Install & Update](/gjsify/guides/install/) page.

## Create and run your first app

<CommandTabs title="Create and run">
  <Fragment slot="gjsify">
    ```bash
    gjsify create hello-gjsify --template gtk-minimal
    cd hello-gjsify
    gjsify install
    gjsify run dev
    ```
  </Fragment>
  <Fragment slot="npm">
    ```bash
    npm create @gjsify/app hello-gjsify -- --template gtk-minimal
    cd hello-gjsify
    npm install
    npm run dev
    ```
  </Fragment>
  <Fragment slot="bun">
    ```bash
    bunx @gjsify/cli@latest create hello-gjsify --template gtk-minimal
    cd hello-gjsify
    bun install
    bun run dev
    ```
  </Fragment>
  <Fragment slot="deno">
    ```bash
    deno run -A npm:@gjsify/cli@latest create hello-gjsify --template gtk-minimal
    cd hello-gjsify
    deno install
    deno task dev
    ```
  </Fragment>
</CommandTabs>

A window titled `hello-gjsify` opens with a label in it. That window is your
`src/index.ts`, bundled into one file and executed by `gjs`.

Leave `--template` off and the CLI asks you which one you want. It needs a
terminal to ask, so in a script the flag is required.

| Template | Runs on | What you get |
|---|---|---|
| `gtk-minimal` | GJS | `Gtk.Window` + `Gtk.Label`, no Adwaita, no Blueprint |
| `adw-canvas2d` | GJS | Adwaita app drawing through the HTML Canvas 2D API |
| `adw-webgl` | GJS | Adwaita app rendering with WebGL and three.js |
| `adw-game` | GJS | Adwaita game shell on Excalibur.js, WebGL with a Canvas 2D fallback |
| `cli` | GJS · Node · Bun · Deno | command-line tool built on yargs |
| `web-server-hono` | GJS · Node · Bun · Deno | HTTP server on Hono |
| `web-server-express` | GJS · Node · Bun · Deno | HTTP server on Express |

## What the CLI generated

```txt title="hello-gjsify"
hello-gjsify/
├── src/
│   └── index.ts        # Gtk.Application entry point
├── package.json        # build / start / dev scripts wired to the gjsify CLI
├── tsconfig.json
└── README.md
```

The scripts are the whole build system:

```jsonc
"scripts": {
  "clear": "gjsify clear dist tsconfig.tsbuildinfo",
  "check": "gjsify tsc --noEmit",
  "build": "gjsify build src/index.ts --app gjs --outfile dist/index.gjs.js",
  "start": "gjsify run dist/index.gjs.js",
  "dev":   "gjsify run build && gjsify run start"
}
```

Run them with whichever toolchain you picked above:

<CommandTabs title="Build and run">
  <Fragment slot="gjsify">
    ```bash
    gjsify run build   # bundle src/index.ts for GJS
    gjsify run start   # launch the bundle
    gjsify run dev     # both, in one step
    gjsify run check   # type-check without emitting
    ```
  </Fragment>
  <Fragment slot="npm">
    ```bash
    npm run build   # bundle src/index.ts for GJS
    npm start       # launch the bundle
    npm run dev     # both, in one step
    npm run check   # type-check without emitting
    ```
  </Fragment>
  <Fragment slot="bun">
    ```bash
    bun run build   # bundle src/index.ts for GJS
    bun run start   # launch the bundle
    bun run dev     # both, in one step
    bun run check   # type-check without emitting
    ```
  </Fragment>
  <Fragment slot="deno">
    ```bash
    deno task build   # bundle src/index.ts for GJS
    deno task start   # launch the bundle
    deno task dev     # both, in one step
    deno task check   # type-check without emitting
    ```
  </Fragment>
</CommandTabs>

Always launch through `gjsify run` rather than calling `gjs` yourself: it sets
`LD_LIBRARY_PATH` and `GI_TYPELIB_PATH` so the bundle finds any native packages
(`@gjsify/webgl`, for instance). `gjsify info` prints those paths if you want to
export them by hand.

## Add a button

Open `src/index.ts`. It is plain GTK reached through `gi://`, with no gjsify
abstraction in the way:

```typescript
import Gtk from 'gi://Gtk?version=4.0';
import Gio from 'gi://Gio?version=2.0';

const app = new Gtk.Application({
    applicationId: 'org.gjsify.hello-gjsify',
    flags: Gio.ApplicationFlags.FLAGS_NONE,
});
```

`applicationId` is the session-bus name your app claims, and every project needs
its own. If you copy this file into a second project, change it there: when two
running apps claim one name, GTK treats the second launch as a remote instance of
the first, forwards its `activate` to that app's window and exits 0 with no window
and no error of its own.

Inside the `activate` handler, next to the label the template already creates:

```typescript
const button = new Gtk.Button({ label: 'Say hello' });
button.add_css_class('suggested-action');
button.connect('clicked', () => title.set_label('Hello yourself!'));

box.append(button);
```

Re-run `dev` and the button is there. For the Adwaita widgets (header bars,
boxed lists, toasts, view switchers) see the
[Widget Gallery](/gjsify/adwaita/), and for a full app shell with navigation and
dialogs see [Native Adwaita Apps](/gjsify/guides/native-adwaita-app/).

## Use Node.js and Web APIs

Write ordinary Node.js and Web code in the same file. The build rewrites
`node:*` imports to their gjsify implementations and injects the globals your
code touches, so there is no import list to maintain:

```typescript
import { readFileSync } from 'node:fs'
import { createServer } from 'node:http'

const html = readFileSync('index.html', 'utf-8')

const server = createServer((req, res) => {
    res.writeHead(200, { 'Content-Type': 'text/html' })
    res.end(html)
})

const port = Number(process.env.PORT ?? 8080)
server.listen(port, () => {
    console.log(`Server running on http://localhost:${port}`)
})
```

`node:fs` runs on `Gio.File`, `node:http` on `Soup.Server`, `process.env` on
`GLib.getenv()`. Web APIs work the same way:

```typescript
const response = await fetch('https://api.example.com/data')
const data = await response.json()

const ws = new WebSocket('wss://echo.example.com')
ws.addEventListener('message', (event) => console.log(event.data))
```

[Packages](/gjsify/packages/overview/) lists what is implemented.

<details>
<summary>Global detection missed something?</summary>

Rare, but it happens with libraries that reach `globalThis` through another
object, which hides the access from static analysis. Keep `auto` on and name the
identifier you need:

```bash
gjsify build … --globals auto,matchMedia
# or a whole group:
gjsify build … --globals auto,dom
```

The [CLI Reference](/gjsify/cli-reference/#known-identifiers) has the full list.

</details>

## If it did not start

Ask the CLI what is missing:

<CommandTabs title="Check your system">
  <Fragment slot="gjsify">
    ```bash
    gjsify system-check
    ```
  </Fragment>
  <Fragment slot="npm">
    ```bash
    npx @gjsify/cli@latest system-check
    ```
  </Fragment>
  <Fragment slot="bun">
    ```bash
    bunx @gjsify/cli@latest system-check
    ```
  </Fragment>
  <Fragment slot="deno">
    ```bash
    deno run -A npm:@gjsify/cli@latest system-check
    ```
  </Fragment>
</CommandTabs>

It prints a line per dependency, names the `@gjsify/*` package that wants each
optional one, and warns when your `@girs/*` types describe a newer library than
the one installed. To install the required set:

<CommandTabs title="Install the system libraries" group="distro">
  <Fragment slot="fedora">
    ```bash
    sudo dnf install gjs gtk4-devel libadwaita-devel libsoup3-devel \
      gobject-introspection-devel blueprint-compiler meson pkgconf-pkg-config
    ```
  </Fragment>
  <Fragment slot="debian">
    ```bash
    sudo apt install gjs libgtk-4-dev libadwaita-1-dev libsoup-3.0-dev \
      gobject-introspection libgirepository1.0-dev blueprint-compiler meson pkg-config
    ```
  </Fragment>
  <Fragment slot="arch">
    ```bash
    sudo pacman -S gjs gtk4 libadwaita libsoup3 \
      gobject-introspection blueprint-compiler meson pkgconf
    ```
  </Fragment>
</CommandTabs>

Two things that trip people up:

- **`gjs` is too old.** 1.86 is the floor. Fedora 43+, Arch and Debian
  forky/sid ship it; Debian 13 (trixie) ships 1.82.3 and will not work.
- **`gjsify: command not found`** after the Node-free bootstrap means
  `~/.local/bin` is not on your `PATH`.
