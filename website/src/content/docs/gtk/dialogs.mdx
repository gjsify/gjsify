Two of these are **windows you show** and two are **surfaces you pop up from a widget**,
and GTK treats the two kinds quite differently: the first is a `GtkDialog` with an action
area, the second a `GtkPopover` with a search entry. libadwaita restyles all four in one
place — a flat titlebar, a framed `paper` in the print preview — and adds nothing else.

<MoreInfo title="What the browser replicas can and cannot do">
All four render their real layout here. Two of them cannot do the one thing their GTK
counterpart exists for: **nothing prints**, because a browser has no print backend, no
CUPS over D-Bus and no spooler, and `<gtk-print-unix-dialog>` therefore takes its printer
list as an input instead of discovering one. The **emoji table is a curated subset** of
GTK's, because GTK's is a compiled 1.2 MB GVariant per language. Both facts are stated
where they are visible: in the dialog's own block below and in each element's header.
</MoreInfo>

## About Dialog

GTK's own about window, and **not** the libadwaita one: a `GtkWindow` whose headerbar
holds a `GtkStackSwitcher` — no title text at all — over four pages. The main page is a
dialog-size logo over the **program name** in bold, then version, comments, website,
copyright and licence as centred labels. The other three pages exist only when they have
content, and each has its own rule: **License** only for a `license-type` of `custom`
*and* a licence string, **System** for any non-empty text, **Credits** for any credit
list, any extra `addCreditSection` or a `translator-credits` that is not the untranslated
gettext sentinel. A dialog with none of the three shows an empty headerbar, which is what
GTK shows.

Setting a `license-type` other than `custom` does something worth knowing: it **overwrites
`license`** with the standard warranty preamble, links it to that licence's URL, and turns
`wrap-license` on.

<MoreInfo title="A credit line carries its own link">
`"Ada <ada@example.org>"` and `"Ada https://example.org"` are both **one** string, and both
render as a link — the same rule `parse_person` applies in libadwaita and
`add_credits_section` applies here. The bracket form is an email, a bare `http(s)` URL is
not, and the link is only as long as the text up to the first space, newline, tab or `>`.
</MoreInfo>

## Emoji Chooser

The popover a text widget opens to insert an emoji, and the whole of it is **search**: a
term matches when it is a **prefix** of a word in the emoji's name or in one of its
keywords, a section with no match at all disappears heading included, and a search that
empties every section shows the *No Results Found* page instead of the list. The toolbar
below the list does two jobs — its buttons jump to a section, and the checked one follows
the scroll position — which is why **Ctrl+N** and **Ctrl+P** move by section rather than by
pixel, and why **Enter** picks the first result.

Picking one emits **emoji-picked** with the Unicode *sequence* (what an entry inserts, not
what a label shows) and records it in **Recents**, capped at 21 with no duplicates. Holding
**Ctrl** keeps the popover open so a second one can be added; a second click on an emoji
with skin tones opens its variants.

<MoreInfo title="Where the emoji come from">
GTK reads `/org/gtk/libgtk/emoji/<lang>.data` — a **compiled GVariant** of about 1.2 MB per
language, holding each emoji's code points, its name in two languages and two keyword
lists. Nothing in a browser can read that serialisation, so `<gtk-emoji-chooser>` ships a
curated table with the same **shape**: the same nine sections in the same order, the same
headings, the same `emoji-picked` sequence and the same prefix search over names and
keywords. It is smaller, and a reader who searches for something it does not ship finds the
*No Results Found* page — which is the same thing GTK shows for a search that matches
nothing.
</MoreInfo>

## Page Setup Dialog

The page setup dialog Unix platforms have instead of a native one: two drop downs, one
label and four buttons. The label is the interesting part — it reports the chosen sheet as
`W × H unit` and puts the **four margins in its tooltip**, and the numbers go through GTK's
own `double_to_string`, which prints two decimals in inch, one in millimetres and then
strips the zeros, so a whole millimetre comes out with no decimal point at all.

The four orientation buttons are one radio group, and `set_page_setup` writes them. A setup
whose margins match no row in the list is **appended** rather than dropped, because that is
what the C does when `add_item` is set — which is the same call this dialog always makes.

<MoreInfo title="The last row opens a dialog you will not see">
The paper list ends with **Manage Custom Sizes…**, and picking it puts the drop down back
to the previous size and then presents the custom-paper dialog. That half runs in GTK and
runs here; the dialog it presents needs the same backends as the printer list, because a
custom paper size is a per-printer thing. So the row resets the selection and stops.
</MoreInfo>

## Print Dialog

Seven notebook pages over a printer list, and **the capabilities are what make it a dialog
rather than a form**. `manual-capabilities` is the half of the mask the *application* can
handle, and every control on the first two pages reads it: copies, reverse, scale, the
two-sided sheet picker, and whether **Preview** appears at all — visible, not merely
enabled. **Collate** needs the `collate` capability *and* a copies count above one, because
collating one copy is nothing.

Three properties only decide what the dialog lets a user reach: **current-page** (without a
page, *Current Page* is insensitive), **support-selection** (without it, *Selection* is not
shown) and **has-selection** (with support but nothing to print, it is insensitive). And
the one control that explains itself: the two page thumbnails under Copies change their
**numbers** with Collate and Reverse, and the second column appears only above one copy.

<MoreInfo title="Nothing here prints">
The replica is the dialog: its layout, its page set and every derivation GTK runs over a
printer's capabilities and options. The **Print** button does what the C's does when no
printer accepts jobs — it is insensitive — and it says so by taking its printer list as an
**input** (`printers`), because GTK's comes from `gtk_print_backend_load_modules` and a
browser has no CUPS. The four option pages (Image Quality, Color, Finishing, Advanced) are
the empty grids the C leaves them in when `_gtk_printer_get_options` has no printer to ask.

One C detail worth naming: **embed-page-setup** is the only thing that makes the paper size
and orientation drop downs sensitive, and it is also what connects their `selected`
handlers. That pairing is ported, so an un-embedded Page Setup page shows two dead drop
downs exactly as GTK does.
</MoreInfo>
