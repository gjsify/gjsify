Showcases are finished, runnable apps. Each one starts with a single command, opens a real GTK 4 window, and is written in ordinary web code: `<canvas>`, WebGL, `fetch`, `XMLHttpRequest`, `RTCPeerConnection`, Express. They are the quickest way to find out whether gjsify can carry the kind of app you want to build, and the source of each one is a working template you can copy from.

## Run one

You need the `gjsify` CLI plus GJS 1.86 with GTK 4. There is nothing to clone:

```bash
gjsify showcase                          # list every showcase
gjsify showcase canvas2d-fireworks       # run one, opens a GTK 4 window
```

The CLI fetches the showcase's npm package on demand, sets up the native typelibs it needs, and launches it. If a system library is missing, `gjsify system-check` names it.

| [`minimalist-browser`](./minimalist-browser/) | A browser shell: URL bar plus an `<iframe>` backed by WebKit | Browser |

## Run it on Node, Bun or Deno

Most showcases open the same GTK 4 window on a different JavaScript engine. Add `--runtime`:

```bash
gjsify showcase canvas2d-fireworks --runtime gjs
gjsify showcase canvas2d-fireworks --runtime node
gjsify showcase canvas2d-fireworks --runtime bun
gjsify showcase canvas2d-fireworks --runtime deno
```

GTK is reached through the [node-gi](/gjsify/projects/node-gi/) bridge on Node, Bun and Deno. Without the flag, gjsify uses `gjs` when it is installed and otherwise the runtime the CLI itself is running on.

Each showcase declares the runtimes it supports in `package.json` under `gjsify.example.runtimes`. Ask for one it does not support and you get a clear error rather than a crash deep in the bundle. `minimalist-browser` and `webrtc-loopback` declare `["gjs"]`, because their native side is a WebKit view and a GStreamer pipeline, so `--runtime` has nothing to offer them. Their browser builds are unaffected: those run on the browser's own WebKit and WebRTC.

More detail: [Runtimes](/gjsify/runtimes/) and the [CLI reference](/gjsify/cli-reference/#run-a-showcase-on-node-bun-or-deno).

## Put one in a web page

Every showcase in the catalog except `express-webserver` also ships a `./browser` entry that mounts into any DOM container:

```ts
import { mount } from '@gjsify/example-dom-canvas2d-fireworks/browser';

const handle = mount(document.getElementById('app')!);
handle.pause();   // stop the render loop
handle.resume();
```

The package name follows the pattern `@gjsify/example-<category>-<name>`, so `adwaita-storybook` is `@gjsify/example-gtk-adwaita-storybook`. The live demos on the showcase pages below are these same modules, mounted by the site.

## Read the source

Every showcase lives under [`showcases/`](https://github.com/gjsify/gjsify/tree/main/showcases) in the gjsify repo. They share one layout: a platform-agnostic module holds the app itself, and a thin shell per target wraps it. `src/gjs/` is the GTK shell, `src/browser/` is the DOM shell, and the file in between imports nothing platform-specific.

That split is what you want to copy. Keep your app logic free of `@gjsify/*` imports, write against the standard APIs, and the same file runs on GTK and in a browser.
