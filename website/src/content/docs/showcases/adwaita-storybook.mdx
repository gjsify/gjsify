A component browser for the Libadwaita widget set: a sidebar of stories, a live preview, and a controls panel wired to each story's arguments. The stories are grouped into nine categories, from Buttons and Boxed Lists to Navigation and View Switching.

Two things to take from it. It is the fastest way to see what a Libadwaita widget looks like and how its properties behave before you commit to it. And it shows the story format gjsify uses: you describe a component once, in a file that imports no renderer, and get a native GTK preview and a browser preview from it.

## Run it on GJS

```bash
gjsify showcase adwaita-storybook
```

A native GTK 4 window opens with real `Adw.*` widgets: an `Adw.NavigationSplitView` for the sidebar, and an `Adw.Breakpoint` that folds it into single-pane navigation when the window gets narrow.

From a checkout of the showcase, `gjsify storybook` does the same thing, and `gjsify storybook --watch` rebuilds and relaunches when you edit a story.

## Run it on Node, Bun or Deno

```bash
gjsify showcase adwaita-storybook --runtime node   # or bun / deno
```

The same native window, with GTK reached through the [node-gi](/gjsify/projects/node-gi/) bridge. One `--app node` bundle serves all three, so there is no per-runtime build and no third copy of a story.

## Run it in the browser

```ts
import { mount } from '@gjsify/example-gtk-adwaita-storybook/browser';

mount(document.getElementById('app')!, { title: 'Adwaita Storybook' });
```

`mount()` renders the storybook into any container through `@gjsify/adwaita-storybook`'s `mountStorybook`, from the same story list. It is responsive: the controls panel folds away below 1000px of container width, and below 620px the sidebar collapses to single-pane navigation.

## Add your own story

A story is two small files plus one optional third, and the split is what lets one description drive several renderers.

- `src/<category>/<name>.meta.ts` holds the `StoryMeta`: title, category, and the controls that drive it. It imports no renderer, and it is the single source of truth.
- `src/<category>/<name>.story.ts` is the GTK twin. It spreads the meta and names the widget: `{ ...meta, component: Adw.X.$gtype }`.
- `src/browser/<category>/<name>.web.ts` is the browser twin, a `StoryElement` that builds `@gjsify/adwaita-web` elements.

Because the controls are declared once, both targets expose the same knobs, and a native screenshot lines up with a browser screenshot. `src/browser/stories.ts` is the shared list that `main.ts` (standalone) and `embed.ts` (`mount()`) both read.

`gjsify storybook` finds every `*.story.ts` on its own. There is no storybook app to maintain: the settings it needs (application id, window title, story directory) live in the `gjsify.storybook` block of `package.json`.

## What it uses

| Package | What it provides |
|---|---|
| [`@gjsify/stories`](https://github.com/gjsify/gjsify/tree/main/packages/framework/stories) | The renderer-free `StoryMeta` contract both targets consume |
| [`@gjsify/storybook`](https://github.com/gjsify/gjsify/tree/main/packages/framework/storybook) | The native GTK renderer behind `gjsify storybook` |
| [`@gjsify/adwaita-web`](https://github.com/gjsify/gjsify/tree/main/packages/web/adwaita-web) | The Adwaita widget set as light-DOM custom elements: rows, buttons, carousel, tab and view switchers, navigation, dialogs |
| [`@gjsify/adwaita-storybook`](https://github.com/gjsify/gjsify/tree/main/packages/web/adwaita-storybook) | The browser renderer: sidebar, preview, live controls, responsive collapse |
| [`@gjsify/devtools`](https://github.com/gjsify/gjsify/tree/main/packages/framework/devtools) | D-Bus and MCP control, so you can screenshot and drive the native window from a script |
