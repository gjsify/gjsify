A small Express 5 blog: a JSON API, server-rendered article pages, and a static frontend. Express comes straight from npm with no fork and no shim in your code.

The demo shows that a Node web app runs on GJS unchanged. `src/index.ts` has no GJS branch anywhere in it, so if you already have an Express service, this is what porting it looks like: nothing.

## Run it on GJS

```bash
gjsify showcase express-webserver
```

There is no window. It runs a GLib main loop and listens on port 3000. Open `http://localhost:3000/` in a browser, or hit the API:

```bash
curl http://localhost:3000/api/posts
# → {"count":…,"posts":[…]}

curl http://localhost:3000/api/posts/hello-gjs

curl http://localhost:3000/api/runtime
# → {"runtime":"GJS","platform":"linux","version":"…","time":"…"}
```

Set `PORT` to listen somewhere else.

`/api/runtime` is the interesting one: it reports which JavaScript engine is serving the request, from `runtimeName` in `@gjsify/runtime`. Run the same bundle on Node and the field changes; nothing else does.

## Run it on Node, Bun or Deno

```bash
gjsify showcase express-webserver --runtime node   # or bun / deno
```

One `--app node` bundle serves all three. From `showcases/node/express-webserver/` in a checkout you can also run the two builds side by side:

```bash
gjsify run build
gjsify run start        # the --app gjs bundle
gjsify run start:node   # the --app node bundle
```

Same `src/index.ts`, two bundles: `dist/index.gjs.js` and `dist/index.node.mjs`.

## What it uses

| Package | What Express needs it for |
|---|---|
| [`@gjsify/http`](https://github.com/gjsify/gjsify/tree/main/packages/node/http) | `http.createServer()`, `Server.listen()`, and the `IncomingMessage` and `ServerResponse` surface |
| [`@gjsify/stream`](https://github.com/gjsify/gjsify/tree/main/packages/node/stream) | `req.pipe(res)` and body parsing |
| [`@gjsify/events`](https://github.com/gjsify/gjsify/tree/main/packages/node/events) | `EventEmitter`, which Express and its middleware lean on throughout |
| [`@gjsify/url`](https://github.com/gjsify/gjsify/tree/main/packages/node/url) | URL parsing in the route matcher |
| libsoup 3.0 | The TCP listener and HTTP/1.1 parser under `@gjsify/http` |

You install none of them. `gjsify build` rewrites the `node:` imports for you, which is what [How it works](/gjsify/how-it-works/) walks through.

## Copy the structure

[`showcases/node/express-webserver/`](https://github.com/gjsify/gjsify/tree/main/showcases/node/express-webserver)

- `src/index.ts` is the whole app: middleware, the JSON API, the server-rendered pages and `app.listen()`.
- `src/data/posts.ts` holds the in-memory post fixtures the API and the pages both read.
- `src/public/` is the static frontend, served with `express.static()`.

Compared with the GTK showcases there is no shell to write, because a server has no UI. Build it, run it, and the only per-target file is the bundle.
