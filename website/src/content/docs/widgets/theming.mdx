`@gjsify/adwaita-web` renders the widget set as **light-DOM custom elements** styled by
one global stylesheet. That is a deliberate choice: light DOM keeps the widgets
overridable from the outside and trivially server-renderable. The cost is that a host
page's CSS can reach in — so each widget re-establishes the Adwaita typographic and
box-model context at its own boundary, and the **design tokens below are the sanctioned
way to change how it all looks**.

That is [ADR 0010](https://github.com/gjsify/gjsify/blob/main/docs/adr/0010-adwaita-web-style-isolation.md)
decision 2, and it means two things in practice:

- **Tokens are API.** They are named and documented on this page, and they keep working
  if the components ever move behind a shadow boundary — custom properties cross one,
  ordinary CSS rules do not.
- **You can still just write CSS.** Light DOM is not a wall. A higher-specificity rule
  wins as it always does; the tokens are the route that survives upgrades.

## Re-theme with tokens

Set the properties anywhere above the widgets — `:root` for the whole page, or one
container for a subtree:

```css
:root {
    --accent-bg-color: #9141ac;
    --accent-fg-color: #ffffff;
    --window-bg-color: #f6f5f4;
}

/* Or scope it: only this panel is purple. */
.brand-panel {
    --accent-bg-color: #9141ac;
}
```

Every token has a **light** default and a **dark** counterpart re-declared under the
dark theme, so a value you set in one place applies to both unless you scope it. The
values listed here are the light defaults.

<div class="adw-token-tables">
  {ADWAITA_TOKEN_GROUPS.map((group) => (
    <div key={group.title}>
      <h3 id={group.title.toLowerCase().replace(/[^a-z0-9]+/g, '-')}>{group.title}</h3>
      <table>
        <thead>
          <tr>
            <th>Token</th>
            <th>Light default</th>
          </tr>
        </thead>
        <tbody>
          {group.tokens.map((token) => (
            <tr key={token.name}>
              <td><code>{token.name}</code></td>
              <td><code>{token.value}</code></td>
            </tr>
          ))}
        </tbody>
      </table>
    </div>
  ))}
</div>

<p>
  <strong>{ADWAITA_TOKEN_COUNT} tokens</strong> in {ADWAITA_TOKEN_GROUPS.length} groups — read out of
  the stylesheet that declares them when this page is built, so the contract documented here
  is the contract that shipped.
</p>

## What is not a token

The **accent** is a token like any other on the web, but on the native GTK side it comes
from the desktop's own accent setting through `AdwStyleManager`. If you are theming an
app that renders on both, set the token for the web and let GNOME decide on the desktop —
that is what a user changing their accent in Settings expects.

Font tokens work the same way: `--document-font-family` and `--monospace-font-family`
exist here because a browser has no style manager to ask, and they carry the same names
GTK writes at runtime so the override path is identical.
