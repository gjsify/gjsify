**gjsify is a TypeScript framework for native desktop apps.** You write TypeScript
and you get a real GTK 4 / Adwaita application: one native process, no bundled
browser engine, no Node.js running alongside it. Your code is executed by GJS,
GNOME's own JavaScript runtime, and gjsify supplies the pieces GJS never had, so
`node:fs`, `fetch`, `WebSocket`, `<canvas>` and a large slice of npm work there.
GTK and libadwaita stay exactly as they are, reached through `gi://` imports.

**What you can build with it:** a desktop app with the full Adwaita widget set, a
game rendering with WebGL into a real `Gtk.GLArea` or with Canvas 2D into a
`Gtk.DrawingArea` (three.js and Excalibur.js run unmodified), a command-line tool,
or an HTTP server on Express or Hono. `gjsify create` has a starter template for
each of those. The same source
can also be built for the browser, and the whole toolchain runs on GJS, so you can
develop and ship on a machine with no Node.js installed.

Start here: [Getting Started](/gjsify/getting-started/) takes you from nothing to a
window on screen.

## Choose the target when you build

Where your code runs is a flag on the build, not a decision baked into your app:

| `gjsify build --app` | Runs on | Reach for it when |
|---|---|---|
| `gjs` | GJS, on Linux | you are shipping a native GNOME app. This is the main target. |
| `node` | Node.js, Bun and Deno, on Linux, macOS and Windows | you want GTK code on a machine with no GJS, or a build step in CI |
| `browser` | any modern browser | you want a web build of the same source, Adwaita included |

The flag defaults to whatever runtime is running the CLI, so a global GJS install
builds `gjs` bundles and `npx @gjsify/cli` builds `node` ones. [Runtimes](/gjsify/runtimes/)
covers what each target gives you; [Platform Support](/gjsify/platform-support/)
answers the operating-system question.
