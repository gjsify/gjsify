Reach for a **boxed list** whenever you build a settings or detail screen: a set
of related rows gathered into one rounded card. The card is a **preferences
group**, and each row is a small self-contained control (a toggle, a text field,
a drop-down, a button).

:::note
The previews run the browser port, so behaviour Libadwaita drives natively (an
entry's apply button, a spin button's repeat, the press feedback on a row) can be
simplified here.
:::

## Preferences Group

Start with the group: it draws its rows as one rounded card. Give it a **title**,
a **description**, and a **header-suffix** widget (a button or switch pinned to
the trailing edge of the header). Stack several groups to build a full
preferences page.

<AdwWidget title="Adw.PreferencesGroup" blueprint="adwaita/preferences-group.blp">
  <Fragment slot="gjs">
    ```ts
    import Adw from 'gi://Adw?version=1';
    import Gtk from 'gi://Gtk?version=4.0';
    import ui from './preferences-group.blp';

    Adw.init();
    const builder = Gtk.Builder.new_from_string(ui, -1);
    const signOut = builder.get_object('sign_out') as Gtk.Button;
    signOut.connect('clicked', () => console.log('Sign out'));
    ```
  </Fragment>
  <Fragment slot="webloader">

  </Fragment>

## Action Row

The general-purpose row: a **title** with an optional **subtitle**, plus
**prefix** and **suffix** slots for extra widgets (an icon on the leading edge, a
button or chevron on the trailing edge). Mark it **activatable** and the whole
row responds to a click, which is how you open a detail page.

## Combo Row

Pick one option from a fixed list. The row shows an inline **drop-down**, and the
selection is an index into the model you gave it, not the string itself.

The list is the **model** property, a `Gtk.StringList` in the Blueprint below. Write
`model` before `selected`: GtkBuilder sets properties in the order the file gives
them, and setting a model resets the selection, so a `selected` written first ends
up on the first item. In code the model can also be an array of plain strings, or of
`{ value, label }` objects when the value you store differs from the text you
show — `{ label: 'Blue' }` on its own is addressed by `'Blue'`.

<AdwWidget title="Adw.ComboRow" blueprint="adwaita/combo-row.blp">
  <Fragment slot="gjs">
    ```ts
    import Adw from 'gi://Adw?version=1';
    import Gtk from 'gi://Gtk?version=4.0';
    import ui from './combo-row.blp';

    Adw.init();
    const builder = Gtk.Builder.new_from_string(ui, -1);
    const row = builder.get_object('row') as Adw.ComboRow;
    row.connect('notify::selected', () => console.log(`Accent ${row.selected}`));
    ```
  </Fragment>
  <Fragment slot="webloader">
    ```js
    import '@gjsify/adwaita-web';

    const row = document.querySelector('#row');
    row.addEventListener('notify::selected', () => console.log(`Accent ${row.selected}`));
    ```
  </Fragment>
  <Fragment slot="nativescriptloader">

  </Fragment>

The model stays live. Assign a new one whenever your data changes and the row
follows — the visible list, the inline value and the chevron, which the row hides
while there is nothing to choose between:

```ts
const row = document.querySelector('adw-combo-row');

row.model = ['Blue', 'Teal'];
row.selectedValue = 'Teal'; // pick by value; `row.selected` picks by index
row.selectedItem; // → { value: 'Teal', label: 'Teal' }

row.model = [...row.model, { value: 'g', label: 'Green' }];
```

That last line adds one option and leaves the two already on screen alone, so a
list that grows does not flicker or lose the reader's place.

Reading `row.model` hands you a copy of the list, so you can build the next one
out of it — push, filter, rename an item — and nothing on screen moves until you
assign it back.

The same array is what [`<gtk-drop-down>`](/gjsify/gtk/controls/#drop-down) takes,
under the same `model` name — and so do `Adw.ComboRow` on NativeScript and the
`<AdwComboRow model={…}>` prop in React Native, so one model moves between the
surfaces without being rewritten.

`Gtk.StringList` is the other spelling of that same array, and the code windows
above use it because it is what a GJS author writes. On GJS it is the real
`GtkStringList`; on the web and NativeScript ports it is an `Array` subclass, so
`model = ['Blue', 'Teal']` and
`model = new Gtk.StringList({ strings: ['Blue', 'Teal'] })` are the same write and
either one reads back the same list.

:::note
`model` is what this row and the drop-down take, and only they. The widgets whose
contents are **child widgets** — sidebar, tab view, toggle group, view stack,
carousel — have no such property, here or in Libadwaita: their items are added one
at a time. Keep using what each one already gives you — `<adw-sidebar>`'s
`sections`, `<adw-tab-view>`'s `appendPage()`, or plain child elements in markup
for the toggle group, the view stack and the carousel.
:::

and minus steppers and optional decimal digits, which fits settings like a font

## Expander Row

Tuck advanced or grouped settings out of the way. The row **discloses** its
nested rows when expanded, and it can carry an **enable switch** that gates the
whole section.

<AdwWidget title="Adw.ExpanderRow" blueprint="adwaita/expander-row.blp">
  <Fragment slot="gjs">
    ```ts
    import Adw from 'gi://Adw?version=1';
    import Gtk from 'gi://Gtk?version=4.0';
    import ui from './expander-row.blp';

    Adw.init();
    const builder = Gtk.Builder.new_from_string(ui, -1);
    const row = builder.get_object('row') as Adw.ExpanderRow;
    const host = builder.get_object('host_row') as Adw.EntryRow;
    row.connect('notify::expanded', () => host.grab_focus());
    ```
  </Fragment>
  <Fragment slot="webloader">

## Button Row

row behaves like a button. It takes an optional **start icon** and the usual
Adwaita style classes (`.suggested-action`, `.destructive-action`).
