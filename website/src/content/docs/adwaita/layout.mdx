These four containers give an Adwaita window its shape. Use a **clamp** to hold
content at a readable width, a **header bar** for the top chrome, a **toolbar
view** to frame content between fixed bars, and a **wrap box** to let a run of
children flow onto new lines. None of them hold data: they position what you put
inside and adapt as the space around them changes.

A NativeScript template reaches these widgets through its `xmlns`, and the namespace
is a MODULE: NativeScript loads it and reads the element name off its exports, so
`xmlns:adw="~/adw"` needs an app-local `app/adw.ts` that re-exports what the markup
names. A bare package specifier there does not resolve. There is one barrel per
library, `~/adw` for `Adw.*` and `~/gtk` for `Gtk.*`, because the prefix is the only
thing in XML that can say which library a widget belongs to. Point both at one module
and `<adw:Button>` silently builds the GTK button.

Every NativeScript tab in this gallery was inflated on an Android device before it was
written down.
[`adwaita-gallery-nativescript`](https://github.com/gjsify/gjsify/tree/main/showcases/dom/adwaita-gallery-nativescript)
loads each template through NativeScript's own `Builder` and asserts the view tree it
built. That is the only way to tell a template that renders from one that renders
something else: an attribute arrives as a string, and a child a widget has no slot for
is added to the layout anyway.

The wrap box only recently joined them. `@gjsify/gtk-host` had no child policy for
`AdwWrapBox`, so a child placed in one was refused by name. That was deliberate: a
renderer guessing the policy would call `add`, `append` or `set_child` and be wrong at
exit 0. The policy is now curated against libadwaita, so the block has a tree like the
other three.

React Native primitives go inside these containers too, through
[`@gjsify/react-native`](/gjsify/frameworks/react-native/). The Adwaita element is the
same one the React tab shows, and a `<View>` or `<Text>` sits in its default slot. The
clamp, the header bar and the toolbar view carried a tab for that pairing, and they were
the only three blocks on the site with one, so the [React Native
page](/gjsify/frameworks/react-native/#adwaita-widgets) carries it in full instead. Two
facts from there are worth having before you try it. The primitives need their token
scales installed with `configureStyle({ tokens })` before the first render, because a
class naming a token you have not declared throws out of the render and leaves an empty
window at exit 0 with nothing in the log. And such a tree is a GTK window rather than a
phone screen, which is why it was never the NativeScript tab.

Libadwaita is the reference, typed by
[`@girs/adw-1`](https://www.npmjs.com/package/@girs/adw-1).
[`@gjsify/adwaita-web`](https://github.com/gjsify/gjsify/tree/main/packages/web/adwaita-web)
and [`@gjsify/adwaita-nativescript`](https://github.com/gjsify/gjsify/tree/main/packages/nativescript-bridge/adwaita)
follow its naming, and where a port differs, the window that shows it says so. Both
answer `gi://Adw` and `gi://Gtk`. On NativeScript that resolves once you build with
`gjsify build --app nativescript --gi-renderer`.

:::note
The previews run the browser port, so behaviour Libadwaita drives natively (a
toolbar view revealing each bar independently, a clamp's tightening threshold)
can be simplified here.
:::

## Clamp

Wrap long-form content in a clamp so it stops growing at a **maximum width** and
stays centred in anything wider. As the window shrinks, the clamp starts
tightening the child once it passes the **tightening threshold**. That keeps text
at a comfortable measure on a large display without wasting room on a small one.

This block is written in a different shape from the others on the page. The layout
exists once, as a Blueprint file, and every surface builds that file: GTK compiles it
to GtkBuilder XML, and the web and NativeScript ports build its `?shared-tree`
projection. The preview is that projection, built by `@gjsify/adwaita-web`, and
**Blueprint** under it is the file. The **Web Components** and **NativeScript** tabs of
**Code** hold the files of a project, picked in the small row under the tab bar. The first
is the same layout in the port's own markup, `index.html` or `views/clamp.xml`, generated
from the Blueprint file when the site is built, so the ids match. The code that goes with
it reaches an element by its id, which is where the platforms differ: the web clamp takes
its size as an attribute, the other two as a property. The file marked **(Blueprint)** is
that same code building the layout from the Blueprint file instead of the markup.

The first tab is one program for four runtimes. Built with `gjsify build --app gjs` it
runs on GJS, and built with `--app node` the same source runs on Node.js, Deno and Bun
through `node-gi`. It calls `Adw.init()` so that the builder knows `Adw.Clamp` in a
bare script too; inside an `Adw.Application` the call is harmless.

<AdwWidget title="Adw.Clamp" blueprint="adwaita/clamp.blp">
  <Fragment slot="gjs">
    ```ts
    import Adw from 'gi://Adw?version=1';
    import Gtk from 'gi://Gtk?version=4.0';
    import ui from './clamp.blp';

    Adw.init();
    const builder = Gtk.Builder.new_from_string(ui, -1);
    const clamp = builder.get_object('clamp') as Adw.Clamp;
    const label = builder.get_object('label') as Gtk.Label;
    label.label = 'Reached by its Blueprint id.';
    clamp.maximumSize = 560;
    ```
  </Fragment>
  <Fragment slot="webloader">
    ```js
    import '@gjsify/adwaita-web';

    const clamp = document.querySelector('#clamp');
    const label = document.querySelector('#label');
    label.label = 'Reached by its id.';
    clamp.setAttribute('maximum-size', '560');
    ```
  </Fragment>
  <Fragment slot="nativescriptloader">
    ```ts
    import { type Adw, type Gtk } from '@gjsify/adwaita-nativescript';
    import { Builder } from '@nativescript/core';

    const clamp = Builder.load({ path: '~/views', name: 'clamp' }) as Adw.Clamp;
    const label = clamp.getViewById<Gtk.Label>('label')!;
    label.label = 'Reached by its id.';
    clamp.maximumSize = 560;
    ```
  </Fragment>
</AdwWidget>

## Header Bar

The standard top chrome of an Adwaita window. Put a **title widget** in the
centre, usually a window title with a subtitle, and **pack** controls to the
start and end edges: navigation on the leading side, menu and action buttons on
the trailing one.

{/* A header bar is as wide as the window GTK gives it. The `.blp` cannot say that,
    so the stage stretches it: without this it shrank to its three children. */}
<AdwWidget title="Adw.HeaderBar" blueprint="adwaita/header-bar.blp" stage="flex-direction: column; align-items: stretch;">
  <Fragment slot="gjs">
    ```ts
    import Adw from 'gi://Adw?version=1';
    import Gio from 'gi://Gio?version=2.0';
    import Gtk from 'gi://Gtk?version=4.0';
    import ui from './header-bar.blp';

    Adw.init();
    const builder = Gtk.Builder.new_from_string(ui, -1);
    const title = builder.get_object('window_title') as Adw.WindowTitle;
    const menuButton = builder.get_object('menu_button') as Gtk.MenuButton;
    title.subtitle = 'draft.md';

    const menu = new Gio.Menu();
    menu.append('New Window', 'app.new-window');
    menu.append('Preferences', 'app.preferences');
    menu.append('About', 'app.about');
    menuButton.menuModel = menu;
    ```
  </Fragment>
  <Fragment slot="webloader">
    ```js
    import '@gjsify/adwaita-web';

    const title = document.querySelector('#window_title');
    const menuButton = document.querySelector('#menu_button');
    title.setAttribute('subtitle', 'draft.md');

    menuButton.menuModel = [
        { label: 'New Window', action: 'app.new-window' },
        { label: 'Preferences', action: 'app.preferences' },
        { label: 'About', action: 'app.about' },
    ];
    ```
  </Fragment>
  <Fragment slot="nativescriptloader">
    ```ts
    import { type Adw, type Gtk } from '@gjsify/adwaita-nativescript';
    import { Builder } from '@nativescript/core';

    const headerBar = Builder.load({ path: '~/views', name: 'header-bar' }) as Adw.HeaderBar;
    const title = headerBar.getViewById<Adw.WindowTitle>('window_title')!;
    const menuButton = headerBar.getViewById<Gtk.MenuButton>('menu_button')!;
    title.subtitle = 'draft.md';

    menuButton.menuModel = [
        { label: 'New Window', action: 'app.new-window' },
        { label: 'Preferences', action: 'app.preferences' },
        { label: 'About', action: 'app.about' },
    ];
    ```
  </Fragment>
</AdwWidget>

## Toolbar View

Frame your content between a **top bar** and a **bottom bar**, typically a header
bar above and an action bar below. Each set of bars reveals and hides
independently, and the content scrolls underneath, so the chrome stays put while
the view moves.

{/* A grid stage, because a toolbar view has no size of its own: its window gives
    it one. A grid's single cell stretches the widget both ways, which a flex row
    did only for the width, and the `.blp` cannot say either. */}
<AdwWidget title="Adw.ToolbarView" blueprint="adwaita/toolbar-view.blp" padding="flush" stage="height: 300px; width: 100%; display: grid; justify-content: stretch;">
  <Fragment slot="gjs">
    ```ts
    import Adw from 'gi://Adw?version=1';
    import Gtk from 'gi://Gtk?version=4.0';
    import ui from './toolbar-view.blp';

    Adw.init();
    const builder = Gtk.Builder.new_from_string(ui, -1);
    const add = builder.get_object('add_button') as Gtk.Button;
    const selection = builder.get_object('selection') as Gtk.Label;
    add.connect('clicked', () => {
        selection.label = 'Selection: 1 item';
    });
    ```
  </Fragment>
  <Fragment slot="webloader">
    ```js
    import '@gjsify/adwaita-web';

    const add = document.querySelector('#add_button');
    const selection = document.querySelector('#selection');
    add.addEventListener('click', () => {
        selection.label = 'Selection: 1 item';
    });
    ```
  </Fragment>
  <Fragment slot="nativescriptloader">
    ```ts
    import { type Adw, type Gtk } from '@gjsify/adwaita-nativescript';
    import { Builder } from '@nativescript/core';

    const view = Builder.load({ path: '~/views', name: 'toolbar-view' }) as Adw.ToolbarView;
    const add = view.getViewById<Gtk.Button>('add_button')!;
    const selection = view.getViewById<Gtk.Label>('selection')!;
    add.connect('clicked', () => {
        selection.label = 'Selection: 1 item';
    });
    ```
  </Fragment>
</AdwWidget>

## Wrap Box

Lay children out in a horizontal line and let them **wrap** onto new lines when
they run out of room. This is what you want for a variable-length run of tags,
chips or filter pills. **Child spacing** sets the gap between items on a line,
**line spacing** the gap between the lines.

<AdwWidget title="Adw.WrapBox" blueprint="adwaita/wrap-box.blp">
  <Fragment slot="gjs">
    ```ts
    import Adw from 'gi://Adw?version=1';
    import Gtk from 'gi://Gtk?version=4.0';
    import ui from './wrap-box.blp';

    Adw.init();
    const builder = Gtk.Builder.new_from_string(ui, -1);
    const wrap = builder.get_object('wrap_box') as Adw.WrapBox;

    const chip = new Gtk.Button({ label: 'Blueprint' });
    chip.add_css_class('pill');
    wrap.append(chip);
    wrap.childSpacing = 12;
    ```
  </Fragment>
  <Fragment slot="webloader">
    ```js
    import '@gjsify/adwaita-web';

    const wrap = document.querySelector('#wrap_box');

    const chip = document.createElement('gtk-button');
    chip.setAttribute('label', 'Blueprint');
    chip.classList.add('pill');
    wrap.append(chip);
    wrap.childSpacing = 12;
    ```
  </Fragment>
  <Fragment slot="nativescriptloader">
    ```ts
    import { Gtk, type Adw } from '@gjsify/adwaita-nativescript';
    import { Builder } from '@nativescript/core';

    const wrap = Builder.load({ path: '~/views', name: 'wrap-box' }) as Adw.WrapBox;

    const chip = new Gtk.Button({ label: 'Blueprint' });
    chip.add_css_class('pill');
    wrap.append(chip);
    wrap.childSpacing = 12;
    ```
  </Fragment>
</AdwWidget>
