Two ways to tell the user something. A **toast** slides a short message over the
content and gets out of the way on its own, so use it when nothing needs to happen
next. A **dialog** puts a modal surface in front of the window and waits for an
answer, so use it when something does. The generic **dialog** takes whatever content
you hand it; the **alert**, **about** and **preferences** dialogs below are the three
shapes an app asks for often enough that libadwaita writes them for you.

<MoreInfo title="How the previews differ from the widget">
The previews hold each dialog **open** and each toast **visible**, which is not
how they behave in an app: there they are modal windows and transient overlays the
user triggers. Each one also sits in a fixed-height stage here so it stays
contained, while a real window sizes and centres itself.
</MoreInfo>

## Toast

A short line of text, optionally with one action button, that floats over the
content for a few seconds and then dismisses itself. You do not add a toast to your
layout: you wrap the page in a **toast overlay** and hand it toasts at runtime.

<MoreInfo title="One toast at a time">
The overlay layers toasts above the bottom edge without displacing anything
beneath, and shows **one toast at a time**. Add a second while the first is visible
and it waits its turn, appearing once the visible one goes away, whether by its
timeout, its close button, its action button or an explicit dismissal. Every port
behaves the same way here, so a queue you tested in the browser holds on the
desktop.
</MoreInfo>

        <!-- description: The description markup to be displayed below the title. -->
        <adw-status-page title="Documents" description="Drag files here to organise them."></adw-status-page>

        // The timeout is in seconds; a second toast added now would be queued and

        overlay.addToast('File moved to Trash', { timeout: 3, buttonLabel: 'Undo' });

        overlay.dismiss();      // dismiss now and show the next queued toast
    </script>

        buttonLabel: 'Undo',
    });

## Dialog

The dialog the other three are built on, and the one to reach for when none of them
fits: it holds **whatever you give it** — one child, no content model of its own — and
it decides for itself whether to be a **floating card** over the window or a **bottom
sheet** across it. Give it a **title** and a flat header with a close button appears;
leave the title off and the content runs to the edges.

<MoreInfo title="How a dialog is dismissed">
Three ways out, and one lock. <kbd>Escape</kbd>, the scrim and the close button all
close the dialog, and all three are gated by **can-close**: while it is off, each of
them raises a `close-attempt` instead and the dialog stays put — which is how you keep
a user in a half-filled form. `force_close()` ignores the lock, so a program can always
leave. Every close returns focus to the element that was focused before `present()`.
</MoreInfo>

<MoreInfo title="Sizing it">
**Content width** and **content height** bound the card, and the browser port
defaults the width to the same 360 px `Adw.Dialog` asks for. On a viewport narrower
than that the dialog switches to a bottom sheet unless you pin **presentation mode**
to `floating`.
</MoreInfo>

<AdwWidget title="Adw.Dialog" padding="flush" stage="height: 360px; width: 100%; position: relative; overflow: hidden; display:flex; align-items:center; justify-content:center;">
  <Fragment slot="preview">
    ```html
    <adw-dialog open title="Preferences">
      <adw-preferences-page title="General">
        <adw-preferences-group title="Appearance">
          <!-- active: Whether the switch row is in the "on" or "off" position. -->
          <adw-switch-row title="Dark style" subtitle="Use a dark colour scheme" active></adw-switch-row>
        </adw-preferences-group>
      </adw-preferences-page>
    </adw-dialog>
    ```
  </Fragment>
  <Fragment slot="gjs">
    ```ts
    import Adw from 'gi://Adw?version=1';

    Adw.init();

    const group = new Adw.PreferencesGroup({ title: 'Appearance' });
    group.add(new Adw.SwitchRow({ title: 'Dark style', subtitle: 'Use a dark colour scheme', active: true }));

    const page = new Adw.PreferencesPage({ title: 'General' });
    page.add(group);

    // ONE child, and it is a PROPERTY (`Adw.Dialog:child`), not a pack. The alert,
    // about and preferences dialogs are this class with a content model added.
    const dialog = new Adw.Dialog({ title: 'Preferences', child: page });

    // `close()` honours can-close, `force_close()` does not; both raise `closed`.
    dialog.present(window);
    ```
  </Fragment>
  <Fragment slot="blueprint">
    ```blueprint
    using Gtk 4.0;
    using Adw 1;

    // A dialog is PRESENTED, not shown: a `.blp` declares it, and the code that owns
    // the window calls `present()` on the object it built.
    Adw.Dialog {
      title: _("Preferences");

      child: Adw.PreferencesPage {
        title: _("General");

        Adw.PreferencesGroup {
          title: _("Appearance");

          Adw.SwitchRow {
            title: _("Dark style");
            subtitle: _("Use a dark colour scheme");
            active: true;
          }
        }
      };
    }
    ```
  </Fragment>
</AdwWidget>

## Alert Dialog

Ask a question the user has to answer: a bold **heading**, some **body** text and a row of
**responses**. Each response is a button with a string ID, and that ID is what reaches your
code. Set the **default** and **close** responses so Enter and Escape do the right thing.

<MoreInfo title="Marking the consequence">
Give one response a **destructive** or **suggested** appearance and the choice reads at a
glance before the reader commits to it.
</MoreInfo>

<AdwWidget title="Adw.AlertDialog" padding="flush" stage="height: 360px; width: 100%; position: relative; overflow: hidden; display:flex; align-items:center; justify-content:center;">
  <Fragment slot="preview">
    ```html
    <adw-alert-dialog
      open
      heading="Delete Project?"
      body="This will permanently remove the project and all of its files. This action cannot be undone."
    >
      <adw-alert-response id="cancel">Cancel</adw-alert-response>
      <adw-alert-response id="delete" appearance="destructive">Delete</adw-alert-response>
    </adw-alert-dialog>
    ```
  </Fragment>
  <Fragment slot="gjs">
    ```ts
    import Adw from 'gi://Adw?version=1';

    const dialog = new Adw.AlertDialog({
        heading: 'Delete Project?',
        body: 'This will permanently remove the project and all of its files. This action cannot be undone.',
    });

    dialog.add_response('cancel', 'Cancel');
    dialog.add_response('delete', 'Delete');
    dialog.set_response_appearance('delete', Adw.ResponseAppearance.DESTRUCTIVE);
    dialog.set_default_response('cancel');
    dialog.set_close_response('cancel');

    dialog.present(parent);
    ```
  </Fragment>
  <Fragment slot="blueprint">
    ```blueprint
    using Gtk 4.0;
    using Adw 1;

    Adw.AlertDialog {
      heading: _("Delete Project?");
      body: _("This will permanently remove the project and all of its files. This action cannot be undone.");

      // `delete` is the destructive one. A response FLAG (`destructive`, `suggested`,
      // `disabled`) is outside the subset `@gjsify/blueprint` holds, so gjsify refuses
      // this file rather than build it — set the appearance from code instead, the way
      // the GJS tab does with `set_response_appearance`.
      responses [
        cancel: _("Cancel"),
        delete: _("Delete"),
      ]

      default-response: "cancel";
      close-response: "cancel";
    }
    ```
  </Fragment>
  <Fragment slot="nativescript">
    ```ts
    import Adw from 'gi://Adw?version=1';

    const dialog = new Adw.AlertDialog(
        'Delete Project?',
        'This will permanently remove the project and all of its files. This action cannot be undone.',
    );

    dialog.add_response('cancel', 'Cancel');
    dialog.add_response('delete', 'Delete');
    // The appearance is the nick, not a constant: `@gjsify/adwaita-core` spells it
    // 'default' | 'suggested' | 'destructive' on every surface.
    dialog.set_response_appearance('delete', 'destructive');
    dialog.defaultResponse = 'cancel';
    dialog.closeResponse = 'cancel';

    // NS substitutes the platform's native confirm() chrome; present() resolves
    // to the chosen response ID.
    const response = await dialog.present();
    ```
  </Fragment>
</AdwWidget>

## About Dialog

Wire this to the _About_ entry in your primary menu and you are done. Fill in the app
metadata and the dialog builds the rest: a large **icon**, the application **name**, a
**developer** line, a **version** pill, and Details, Credits and Legal sub-pages you
never lay out yourself.

## Preferences Dialog

The container behind your _Preferences_ command. Organise it into **pages**, each
holding **groups** of [boxed-list rows](../boxed-lists/). Most apps need only one
page, which is what the example shows.

<MoreInfo title="Pages on the two ports">
In a native window, extra pages sit behind a
[view switcher](/gjsify/adwaita/view-switching/) and you see one at a time; the web
port renders them stacked instead.
</MoreInfo>

<AdwWidget title="Adw.PreferencesDialog" padding="flush" stage="height: 360px; width: 100%; position: relative; overflow: hidden; display:flex; align-items:center; justify-content:center;">
  <Fragment slot="preview">
    ```html
    <adw-preferences-dialog open title="Preferences">
      <adw-preferences-page title="General" icon-name="preferences-system-symbolic">
        <adw-preferences-group title="Appearance" description="Control how the application looks and behaves.">
          <!-- active: Whether the switch row is in the "on" or "off" position. -->
          <adw-switch-row title="Dark style" subtitle="Use a dark colour scheme" active></adw-switch-row>
          <!-- model: The model that provides the displayed items. -->
          <adw-combo-row title="Accent colour" model='["Blue","Teal","Green","Orange","Purple"]' selected="0"></adw-combo-row>
          <!-- adjustment: The adjustment that holds the value of the spin row. -->
          <adw-spin-row title="Font size" value="12" adjustment='{"lower":8,"upper":24}'></adw-spin-row>
        </adw-preferences-group>
      </adw-preferences-page>
    </adw-preferences-dialog>
    ```
  </Fragment>
  <Fragment slot="gjs">
    ```ts
    import Adw from 'gi://Adw?version=1';
    import Gtk from 'gi://Gtk?version=4.0';

    const dialog = new Adw.PreferencesDialog();

    const page = new Adw.PreferencesPage({
        title: 'General',
        iconName: 'preferences-system-symbolic',
    });

    const group = new Adw.PreferencesGroup({
        title: 'Appearance',
        description: 'Control how the application looks and behaves.',
    });

    group.add(new Adw.SwitchRow({ title: 'Dark style', subtitle: 'Use a dark colour scheme', active: true }));
    group.add(new Adw.ComboRow({
        title: 'Accent colour',
        model: new Gtk.StringList({ strings: ['Blue', 'Teal', 'Green', 'Orange', 'Purple'] }),
        selected: 0,
    }));
    group.add(new Adw.SpinRow({
        title: 'Font size',
        adjustment: new Gtk.Adjustment({ lower: 8, upper: 24, value: 12, stepIncrement: 1 }),
    }));

    page.add(group);
    dialog.add(page);
    dialog.present(parent);
    ```
  </Fragment>
