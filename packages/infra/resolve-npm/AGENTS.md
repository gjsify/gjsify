### Slot routing — how `--app <target>` resolves `@gjsify/<X>`

Implemented by `packages/infra/resolve-npm/lib/runtime-aliases.mjs`: reads each package's declared quintuplet at config time and emits a derived alias map COMPOSED UNDER the hardcoded `ALIASES_*_FOR_*` baseline (hardcoded wins on conflict).
|rules: `polyfill` → `@gjsify/<X>/<target>` when the package's `exports` declares that platform-entry subpath (ADR 0014, e.g. `@gjsify/os` → `@gjsify/os/browser`), else no rewrite · `partial` → NO rewrite (the shared impl's degradation IS the contract; VALUE-export parity with the root is the promotion gate to `polyfill`, machine-checked by `platform-entry-parity`) · `native` → `@gjsify/<X>/globals` (re-exports the runtime-native value) · `none` → `@gjsify/empty`.
|ONE hop, deliberately: the map `aliasPlugin` receives is already merged flat across four tiers (derived → curated `ALIASES_*` → per-target overrides → user `--alias`, later wins) and resolves each alias target in exactly one hop (`skipSelf: true`). A resolver CHAIN would apply slot routing to USER aliases — `--alias node:stream=@gjsify/stream` (the node-gi consumer harness's entire mechanism; 34 polyfills declare `node:"native"`) would bounce to `@gjsify/stream/globals` = Node's own builtin, and the suite would measure nothing. Measured: chaining changes 0 of 114 `gjs` and 0 of 148 `node` entries; the only 4 changes on `nativescript` are regressions — which is why `ALIASES_NODE_FOR_NATIVESCRIPT` is deliberately NOT composed (a bridge declaring `nativescript:"native"` in the "I AM the native impl" sense promises a `globals.mjs` it does not ship; open TODO). Composing a table is an explicit per-table decision.
|`aliasPlugin` NEVER rewrites an import whose importer is a `\0gjsify-*` virtual module (`isGjsifyVirtualModuleId`) — gjsify-generated module bodies name the RUNTIME module they need; a user `--alias node:module=…` reaching `gjsGiNodePlugin`'s `createRequire` import once made `@gjsify/module` unbuildable on every runtime.
|a `native`-declared package missing its `globals.mjs` is left UNREWRITTEN with a warn-once — NOT rewritten to `@gjsify/empty`, the same MISSING_EXPORT trap `none` documents below. Every `packages/nativescript-bridge/*` package is in that state, so the empty fallback made `--app nativescript` unable to build ANY of them, unnoticed because no CI job built them. Held by e2e `ns-bridge-bundles`.
|**a consumer needing the POLYFILL BODY of a `native`-slotted package imports its `/core` subpath**, never a build `--alias`: `aliasPlugin` matches EXACT specifiers, so a subpath is never rewritten. `native` stays right for the package (the host value IS what a plain consumer wants); the seam consumer says so at the import. A per-consumer alias instead made `@gjsify/iframe`'s node leg green while its SHIPPING build's port transfer threw — [ADR 0022](../../../docs/adr/0022-webkit-on-darwin.md) § *Amendment — the `node` slot*.
|**a `partial` package's CURATED alias must name its `./<target>` subpath, never the package root.** `partial` is not rewritten by the derived layer, so a curated bare `@gjsify/<X>` hands the bundler the GJS body with `@girs/*` emptied to `{}` — `partial` degrading into "crashes at first use" instead of "degrades at call time" (this shipped for `crypto` + `zlib`). Naming the subpath is only safe at value-export parity, so it stays a per-package curated decision. Machine-checked FATAL by `curated-alias-routing`: no curated bare-specifier alias may resolve to the root of a package that ships a `./browser` entry.
|**the ten `browser:"partial"` slots are RESOLVED as partial, not pending**: `crypto` `dns` `fs` `http` `https` `module` `sqlite` `worker_threads` `ws` `zlib` each ship a real `src/browser.ts`; eight of the ten already MEET the parity gate (only `fs` −34 and `https` −2 do not), yet none is promotable — in every case a named export is unavailable on the browser platform ITSELF (no DNS resolver, no inbound socket, no TLS socket below JS, no synchronous CJS loader, no synchronous WebCrypto digest, no synchronous CompressionStream, no synchronous MessagePort drain, no file-change notification API, no SQLite engine). Each package's row in the Node table names its blocking export. **Corollary: parity is necessary but NOT sufficient** — it passes `sqlite`, whose `DatabaseSync` throws from its constructor; a green `platform-entry-parity` is not a promotion mandate. A routed entry must also have no unconditionally-throwing value export.
|**every browser redirect is NAMED; `@gjsify/empty` is a last resort that must carry a CLASSIFICATION.** `@gjsify/empty` is an anonymous, export-less `export default {}` shared by a dozen unrelated specifiers: in an emitted bundle a DELIBERATE stub is indistinguishable from an ACCIDENTAL alias (the camouflage that let `@gjsify/canvas2d`'s build emit a stray `@gjsify/empty` import unnoticed), and rolldown makes a named import from it a HARD ERROR that blames the empty module, not the module the user imported. So `ALIASES_NODE_FOR_BROWSER_TABLE` names `@gjsify/<X>/browser` wherever an entry exists, and each remaining `@gjsify/empty` carries an inline tag: **(A)** wireable now (`dns/promises`, blocked on a `./browser/promises` subpath) · **(A')** native-available, wants a `/globals` re-export not an empty module (`node-fetch`, `isomorphic-ws`) · **(B)** simulatable but unbuilt (`cluster`→Web Workers, `dgram`→WebRTC data channels, `v8.serialize`→`structuredClone`, `readline`→any stream, `tty.isatty`→`false`) · **(C)** impossible (`http2`, `inspector`; `repl`/`wasi` have no owning package to host a stub). An untagged `@gjsify/empty` is the bug — the tag makes remaining work visible instead of implied.
|**`(C)` gets a NAMED THROWING STUB at `@gjsify/<X>/browser` and the package KEEPS `runtimes.browser:"none"`** (today: `child_process`, `net`, `tls`). The stub exports the module's REAL named shape (the root's value exports — the same `collectValueExports` oracle parity uses) so linking succeeds, and throws a structured `ENOTSUP` naming the MODULE, RUNTIME and CALLING SITE (`err.gjsifyModule`/`gjsifyRuntime`/`gjsifyImporter`; the importer frame is fixed by construction since `unsupported()` is only called from an exported binding). `none` stays honest — the stub does not make the module usable, it makes the unusability legible. Exports whose answer IS platform-independent stay REAL (`net.isIP*`, `tls.checkServerIdentity`, the RFC constant tables, `hasOcspSupport()`→`false`); a blanket thrower would replace one lie with another. The throw helper is deliberately LOCAL per file (a browser platform entry imports NOTHING and cannot leak GJS) — lift to `@gjsify/utils/core` once it grows past a handful. A `(C)` stub self-declares with the `Slot: browser:"none"` marker so `audit-runtimes`' `browser_src_is_unsupported` signal doesn't read the mere existence of `src/browser.ts` as a promotion to `polyfill`.
|**`GI_RENDERERS` (`lib/gi-renderers.mjs`) routes a SPECIFIER, not a package**: `--app <target>` → the widget renderer whose `Adw`/`Gtk` namespace objects answer `gi://Ns?version=X`, plus the GI versions that arm accepts (ADR 0034 stage 9, composed only under `--gi-renderer`). CURATED rather than scanned off `gjsify.widgetVocabulary`: several packages declare themselves renderers and `@gjsify/adwaita-react-native` is no target's answer (Metro owns an RN build), so a scan would have to invent that exclusion. Versions held against gtk-host's `GENERATED_PROVENANCE` by `tests/e2e/gi-renderer-arms` — a GIR bump that moves `Adw-1` fails there, not in a consumer.
