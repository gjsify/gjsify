## Framework — `packages/framework/*`

Composition-first (Remix/Astro/SvelteKit feel). Anything NOT Node/Web/DOM/infra belongs here. Showcases use raw `Adw.Application`+`ApplicationWindow`+`ToolbarView`+`HeaderBar` — the purpose is demonstrating the API, not hiding it; a helper lands here only when it delivers what inline bootstrap cannot (multi-subsystem wiring, convention-over-config, composable lifecycle). **Framework vs DOM:** `packages/dom/` = DOM spec impls; `packages/framework/` = composable widgets/helpers gluing DOM↔GTK without being DOM spec.

### Storybook (`@gjsify/stories` + `@gjsify/storybook`)

Reusable GTK component explorer. Stories = `StoryWidget` subclasses with `static getMetadata(): StoryMeta` (title `"Category/Name"` groups the sidebar; `controls` drive a live two-way-bound Adwaita panel), exported as a `StoryModule`. Consumers add `@gjsify/storybook`, write `*.story.ts`, run `gjsify storybook` — no per-project storybook app. Config is `package.json#gjsify.storybook` and is MACHINE-CHECKED by the portable `storybook` conformance rule ([storybook/README.md](storybook/README.md#the-gjsifystorybook-block-is-machine-checked)). One story serves the GTK / browser (`@gjsify/adwaita-storybook`) / NS (`@gjsify/storybook-nativescript`) renderers via the pure `stories` contract + `storybook-core` logic.

**Self-verify (node-gi capstone):** `installStorybookProbe` + `probeEnabled()` drive a running storybook HEADLESSLY IN-PROCESS, no DBus — how `--runtime node` proves the full Libadwaita gallery renders on Node on Linux AND Windows ([storybook/README.md](storybook/README.md#self-verify-the-node-gi-capstone)).

### Devtools (`@gjsify/devtools` + bridge)

Drive/inspect/**screenshot a running GJS/GTK app over DBus** — self-verify a GUI without a human. Opt-in, prod-safe.

|wire: `this.connect('startup', () => installDevtools(this))` — bus connection + object path exist only after the app registers; GC-roots the service against the DBus self-cycle |enable: `GJSIFY_DEVTOOLS=1 <app>` (else no-op returning `null`) |dest = app-id, path = `<app-dbus-object-path>/devtools`, iface `org.gjsify.Devtools`
|**the CAPTURE is OS-agnostic; the TRANSPORT was the only Linux-shaped part.** `captureWidgetPng` is pure in-process GTK4/GSK — no grim, no portal, no GStreamer, no OS branch. What macOS and Windows lack is the SESSION BUS, so `installDevtools` also speaks GDBus **peer-to-peer** over a `Gio.DBusServer`. Precedence is ONE pure function, `chooseDevtoolsTransport` (spec-checked, four rows), and Linux stays byte-unchanged. Auto-picking a socket is the point: `GJSIFY_DEVTOOLS=1` is a request for a control plane, and a service constructed-but-never-exported is the silent absence the whole transport removes.
|**`installDevtools` is TOTAL — it returns `null`, it never throws.** It is wired into `startup`/`activate` handlers, and GJS LOGS an exception thrown in a handler and SWALLOWS it — so a throw costs the consumer the REST of that handler and reads as "my app hangs with no window". Every failure is one stderr line naming the address and the way out; the fallible work lives in one inner function so totality is structural.
|**the published address file is a CLAIM, and the BRIDGE verifies it** — it outranks the session bus, but a dead one is deleted and resolution continues. An EXPLICIT `--address`/`GJSIFY_DEVTOOLS_ADDRESS` never falls back: pinned on both sides, so a dead one must be reported, not routed around.
|**transport, address hygiene, per-connection exports, address-family flags and the macOS operational facts all live in [devtools/README.md](devtools/README.md)** — the precedence table, why `unix:` and `nonce-tcp:` take OPPOSITE auth flags, why a stale socket is reclaimed only when PROVEN dead, the `dbus-run-session` trap, and the 94 s cold start that means POLL `GetStatus`, never sleep.
|methods (`Screenshot`, `DumpTree`, `FindWidget`, `SendKey`, `ActivateWidget`, `GetStatus`, the GAction bridge, CSS hot-swap, …) with the reason each exists: [devtools/README.md § Generic methods](devtools/README.md#generic-methods-out-of-the-box). ### Bridge pattern

Pairings: `HTMLCanvasElement`(2d)→`Canvas2DBridge`→`Gtk.DrawingArea`(Cairo) | (webgl)→`WebGLBridge`→`Gtk.GLArea`(libepoxy) | `HTMLIFrameElement`→`IFrameBridge`→`WebKit.WebView` | `HTMLVideoElement`→`VideoBridge`→`Gtk.Picture`(gtk4paintablesink).

Protocol: (1) bridge creates the DOM element internally (2) app uses standard DOM API (3) bridge translates GTK↔Web lifecycle (signals/draw_func/render ↔ rAF/events/ready). Each bridge owns an isolated `BridgeEnvironment`. Common API: `onReady(cb)`, `installGlobals()`, element getter, `environment`. DOM backing for `Image`: GdkPixbuf.

`WebGLBridge` names the GL it got (`bridge.rendererInfo`, `isSoftwareRenderer`) — **DIAGNOSTIC ONLY**, a renderer swap keys on a MEASURED frame budget, never this string.

**HiDPI is NOT symmetric between the two canvas bridges, and the asymmetry is a whole bug class.** GTK pre-scales a `Gtk.DrawingArea`'s Cairo context; `Gtk.GLArea` does not. So the GL side reports the DRAWING BUFFER in device pixels while CSS layout size stays logical, and `devicePixelRatio` is an ACCESSOR over the widget's live `get_scale_factor()`. Invisible at scale-factor 1 — every desktop, CI runner and test VM — and it drew each scene into the bottom-left NINTH of its widget on the first scale-factor-3 host. The incident, the identity that fixes it and why only a stub can regression-test it: [webgl/README.md § HiDPI](webgl/README.md#hidpi-the-two-canvas-bridges-are-not-symmetric).

**`WebGLBridge` declares which GL APIs it ACCEPTS, never GLES-only.** `set_use_es(true)` is GLES *exclusively*, and macOS offers no GLES profile at all, so on every darwin host that call left the GLArea permanently in error. The bridge sets `set_allowed_apis(GL | GLES)` and lets GDK pick — and the choice MUST be made before realize, so there is no "retry wider after a failed realize" recovery.
**The darwin GL 4.1 ceiling still costs three things**, all measured — two absent GL 4.3 entry points behind an `epoxyGlVersion() >= 43` gate (libepoxy ABORTS on a missing one), a `shaderSource()` that REWRITES `#version 300 es` so **WebGL2 content DOES draw on darwin** (the predicate is the ARB_ES3_compatibility EXTENSION, not the OS), and the GLES 3.0 spellings that surface at draw time. Construct by construct, plus resize/clone and the WebGL2 overrides: [webgl/README.md](webgl/README.md#the-darwin-gl-41-ceiling). Remaining darwin gaps: `status/open-todos.md`.

### GTK Host (`@gjsify/gtk-host`)

The element model UI-framework renderers (Vue/React/Solid/Angular) bind to — **ADR 0027**, table provenance **ADR 0028**. **The full contract, every measurement and the incident behind each rule below are in [gtk-host/README.md](gtk-host/README.md); a live count written HERE drifted twice.** These rules bind work in this tree: (1) **One table, adapters as subpaths** — no adapter may hold a widget name literal or an insertion rule; hand-maintained per-framework tables stalled `react-gtk`, `react-native-gtk4` and `svelte-gjs`. (2) **The shadow tree is the truth** — `parent`/`first`/`next` are the host's own, anchors never enter the GTK tree, and text goes to the descriptor's `textSink` or is refused BY TAG NAME. (3) **Be loud, because GTK's failure mode is exit 0** — ParamSpec coercion, named refusals, and conformance vectors that read the REAL tree (`./conformance`) and assert IDENTITY across a reorder, not just order. (4) **Two facts, never one** — `attached` (GTK has taken this node) is not `widget !== null` (it has been materialised); and nothing is recorded before GTK agrees, because `materialize` replays it verbatim. Every spec asserts zero GTK diagnostics (`installDiagnosticsGate()`), without which the whole mis-parenting class is invisible. (5) **The table is GENERATED and the type surfaces are gated NEGATIVE-first** — `gjsify tsc` cannot check a type surface, so `scripts/check-type-surfaces.mjs` compiles fixtures whose assertions must FAIL and re-runs each with its load-bearing settings flipped. Counts are deliberately absent here; the gate prints them all on every run. (6) **Both legs are CI-wired per ADR 0030** — `test:gjs` in main.yml's sharded sweep, `test:gjs-on-node` as node-gi.yml's `gtk-host-node` job: one corpus, so a gjs-green/node-red diff is attributable. That needs the two legs to be ONE program, which a per-runtime EXPORT CONDITION breaks — `REVERSE_BRIDGE_ENTRY_ROUTES` and why it is a ROUTE, not a `conditionNames` change, is owned by [rolldown-plugin-gjsify/AGENTS.md](../infra/rolldown-plugin-gjsify/AGENTS.md). (7) **One vocabulary, across every surface that DECLARES itself one** — `gjsify.widgetVocabulary` per package, joined to the readers in `scripts/widget-surfaces.mjs`; declared-with-no-reader FAILS, so a fifth surface joins by declaring itself. `scripts/check-vocabulary-alignment.mjs` (required, self-testing) wants a shared spelling/key or a divergence declared WITH A REASON; undeclared, unreasoned, stale and redundant all fail (**ADR 0034**). **ADR 0029** is done: the generator reads `@girs/<ns>/vocabulary`, not GIR XML. (8) **Three adapters — `/solid`, `/vue`, `/react`; the measurements are in the README, one routing fact is here:** `/react` REQUIRES `--define 'process.env.NODE_ENV="production"' --exclude-globals navigator`, or `--globals auto` answers `document`/`navigator` with the GTK-backed DOM registers and the bundle silently grows gi://Gdk, GdkPixbuf, Pango, PangoCairo. (9) **`/fonts`**: `initFonts()`, the shipped-face call — subpath, explicit, error-code-keyed (ADR 0038 § Amendment). (10) **TWO placement axes: `placement` says whether the child policy applies at all** (**ADR 0045**) — `parented` (absent = every widget but five) beside `portal`, PRESENTED against its parent and never parented by it. `close` is the FORCED one, presenting is DEFERRED on `notify::root`, and a portal counts for nothing in four sibling walks or in `addressesOf`. Subclasses are NAMED, with a spec walking `type_is_a(Adw.Dialog)` so libadwaita's next dialog fails the suite instead of a user's app.

### GTK→DOM Event Bridge (`@gjsify/event-bridge`)

`attachEventControllers(widget, getElement)` attaches GTK4 controllers → DOM events: EventControllerMotion→pointer/mouse move+enter/leave/over/out | GestureClick→pointer/mouse down/up, click, dblclick, contextmenu | EventControllerScroll→wheel | EventControllerKey→keydown/keyup | EventControllerFocus→focus/focusin/blur/focusout. W3C UIEvents dispatch; GTK widget-relative coords → offsetX/Y/clientX/Y; `key-map.ts` maps ~80 Gdk keyvals → DOM key/code (L/R modifiers, Numpad location). Canvas2D/WebGL bridges call it in their constructors. Event classes live in `@gjsify/dom-events`.

### Context factory registry

`HTMLCanvasElement.registerContextFactory` — `@gjsify/canvas2d` registers `'2d'` (Cairo); `@gjsify/webgl` registers `'webgl'`/`'webgl2'` via subclass override + fallthrough.

**Framework packages** (`packages/framework/<name>/`): flat `@gjsify/<name>` (NOT `framework-<name>`), composition-first, no top-level side effects in `index.ts`. Global registration is decided by OWNERSHIP, not pillar membership, and **[ADR 0012](../../docs/adr/0012-framework-register-ownership.md) carries all five rules with the bug behind each**: don't re-register what a Web/DOM pillar owns (import its *granular* register subpath from the module that needs it — a second registration silently REPLACES the pillar's factory); ship a `/register` only for globals you own; follow the FULL tree-shakeable convention ([docs/register-convention.md](../../docs/register-convention.md)) when you do; and keep `installGlobals()` and `/register` installing the SAME set. One consequence is spelled out nowhere else: a register import that is a FUNCTIONAL dependency must survive the `--app node` alias layer, so `isGjsSourceBuild` in `app/node.ts` is the single gate and must stay the same question `emptyGirs` asks — the two disagreeing dropped canvas2d's `'2d'` factory on the node target. Current exceptions: `@gjsify/iframe/register`, `@gjsify/canvas2d/register`, `@gjsify/webgl/register`.
