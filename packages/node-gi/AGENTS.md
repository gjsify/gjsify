### Axis 5 — GI/GObject runtime for Node (`@gjsify/node-gi`, the `gi://` reverse bridge)

Run **unchanged GJS/GObject-Introspection code under Node.js** — one source builds + runs via `--app gjs` AND `--app node`. `@girs/*` types already serve both (the ambient `declare module 'gi://…'` mapping is platform-neutral). node-gtk (`refs/node-gtk`) is the read-only derivation source, NOT a convention model (camelCase-only, EventEmitter `.on`, free `registerClass` deliberately not copied).
|decisions (locked): **vendored** in `packages/node-gi/*` (MIT headers + credits to romgrk/node-gtk); native engine ported to **N-API/node-addon-api** (ABI-stable — one prebuild per platform, no per-Node-ABI matrix) AND **girepository-2.0** (the standalone `girepository-1.0` node-gtk linked is gone on GLib ≥ 2.80; GJS's `gi/repo.cpp` is the modern-API reference); first milestone = headless core (GLib+GObject+Gio+GIRepository), GTK/Adw layered after.
|three entry syntaxes, ONE backend (as GJS itself: `gi://` ESM + legacy `imports.gi` share the define): `import Gtk from 'gi://Gtk?version=4.0'` · bare built-ins (`gettext`/`system`/`cairo`/`console`) · legacy `imports.gi.X`. GJS overrides + globals carried over via the SAME detect→inject pipeline run in reverse: core overrides (GLib/GObject/Gio/Gtk/cairo from `gjs/modules/core/overrides`), the `gi` require+`__version__` guard, dual snake_case+camelCase, `.connect()/.emit()/…`, `GObject.registerClass`, `Gio._promisify`, legacy `imports.*` modules (signals/mainloop/lang/byteArray/format/package).
|**prototypes resolve members, as in gjs** (#1175): `Ns.Class.prototype` materializes its introspected methods on first look-up, and a wrapper resolves through the prototype of its runtime GType BEFORE the native fallback. An instance used to ignore its prototype ENTIRELY — the write stuck, the native method still ran, and a spy-based test reported itself installed while measuring NOTHING (`@gjsify/zlib`: `Expected 0 to be greater than 0`). Conformance `prototype-chain`; lookup order + 3 deliberate divergences: [docs/node-gi-gjs-surface.md](../../docs/node-gi-gjs-surface.md) § Class prototypes.
|**an instance's [[Prototype]] IS its class prototype** — set the LINK, never bolt a `$gtype` getter onto instances: `constructor` is RESERVED (the get trap hands it to the bare target), so with only the USER_PROTO symbol every wrapper answered `Object`, `inst.constructor.$gtype` was undefined and `GObject.type_name(…)` `null` — 99 of `@gjsify/gtk-host`'s 125 node-leg failures, every one `No descriptor registered for null`. The class prototype's own `constructor` back-link already IS the object `requireGi` returns (`linkInstanceProto`, both on first wrap and on a USER_PROTO upgrade). Conformance `instance-constructor`.
|**`vfunc_*` is an OWN member of the class prototype**: `native.hasClassVfunc` gates it, `native.callClassVfunc` dispatches against the PROTOTYPE's GType (parents + implemented interfaces walked, so `Gtk.Buildable.add_child` — a slot with no method form, which ADR 0027 § Context rests on — is reachable). Before, `vfunc_*` fell through to the ONE shared `vfuncChainProto`, which traps `get` only: the wrapper resolves by DESCRIPTOR, so `inst.vfunc_add_child` was `undefined` while the prototype's was a thunk that needed a registerClass record and THREW on a plain instance. A NON-addressable name still falls through to that thunk — that is what keeps `super.vfunc_dispose()` working (GI_UNKNOWN struct offset). Two consequences to keep: `collectVfuncs` STOPS at an own `CLASS_INFO`, else a base vfunc materialized before a subclass is registered gets collected as that subclass's OWN override; and a DECLARED-but-unimplemented vfunc (`vfunc_notify`) THROWS on gjs 1.88.1 at the property read while node-gi reports it absent — divergence kept, not ledgered. Conformance `vfunc-instance-dispatch`.
|**wrong-typed args throw, methods carry gjs's `length`**: utf8/object IN args are type-checked exactly like gjs (byte-identical messages; conformance `wrong-arg-type-errors`) — GTK's failure mode for a passed-through wrong pointer is ONE CRITICAL at exit 0, which made six gtk-host refused-operation recoveries dead code on node; `Function.length` = the JS-visible IN-arg count, derived from the SAME skip pre-scan the invoke consumes args with (`classMethodArity`, conformance `callable-arity`). Measured divergences left open (caller-alloc out-array + destroy-notify arity, null/undefined leniency): [docs/node-gi-gjs-surface.md](../../docs/node-gi-gjs-surface.md) + open-todos.
|layers: **L0 native engine** (GIArgument/GValue marshalling, signals/closures/vfunc chain-up, the toggle-ref + two-pass-weak + GLib-idle teardown GC dance — preserve node-gtk's #446/#439 ownership fixes; `napi_ref`+finalizers, NEVER call into GObject/JS during GC) → **L1 GJS-compat runtime** → **L2 gjsify integration** → **L3 examples+tests** (dual gjs+node).
|**an EMPTY `napi_ref` does not mean the finalizer ran** (#1475): V8 resets the weak persistent inside the first-pass weak callback, during GC, while Node defers the finalize callback to a SetImmediate. So `SettleCollectedInstance` (the resurrection path) must NOT free the collected wrapper record in that window — the allocator hands the identical block straight to the fresh wrapper, and the stale finalizer then queues a teardown for the LIVE one: its toggle ref is removed, the GObject is freed under a reachable JS wrapper, and the record is double-freed. Symptom `g_object_weak_unref: couldn't find weak ref` + `STATUS_HEAP_CORRUPTION` on Windows, SIGSEGV on Linux, and it VANISHES under `NODE_GI_TOGGLE_DEBUG=1` (the log's own allocations recycle the freed block). Ownership of the free therefore follows the finalizer, never the collection. Regression: `gc-identity` case 4b — the vehicle has to be a BORROWED C pointer (`g_cancellable_push_current`), because anything that refs the object toggles its wrapper UP and pins it.
|**a GWeakNotify does NOT mean the GObject died**: `g_object_run_dispose` fires every `GWeakNotify` and clears every `GWeakRef` on an object that goes on LIVING (measured, glib 2.88.3) — so every `run_dispose()` a program makes walks the weak-ref net whose own comment called it defensive and unreachable, as does `gtk_native_dialog_destroy()`, documented to keep the object's references (measured, GTK 4.22.4). NOT `gtk_window_destroy()`, measured on the same GTK — it unrealizes and unrefs; `run_dispose` on widget destroy was GTK3's `gtk_widget_destroy`. Reading the notify as "C finalized it" made the teardown skip its `g_object_set_qdata(obj, quark, nullptr)`, leaving a LIVE GObject holding a qdata pointer to the record the teardown then freed; the next re-wrap read that freed record's `handle_ref` (`napi_get_reference_value` → SIGSEGV) or the recycled block reached the drain as `RunTeardown` → `g_object_get_qdata` on garbage. So the DETACH (qdata + queued toggles) happens IN the notify, the last moment the pointer is addressable, under `g_queue_mutex` — which also pairs it with `RunTeardown`'s read of `inst->gobject`, unlocked on both sides until now. An atomic exchange there would drop the data race and KEEP the bug: the reader may still act on a pointer the notify is about to invalidate. Only `g_object_remove_toggle_ref` stays outside the lock (it re-enters JS); the napi flip the notify now does is gated on `g_toggle_shutdown` like every other one, because glib notifies from any thread at any time. Regression `gc-identity` case 4c. THE PRICE, kept on purpose and pinned by case 4d: an object surviving `run_dispose` LOSES wrapper identity — C hands back a NEW wrapper, and every JS field on the old one with it — and that re-wrap adds a SECOND toggle ref, for which glib delivers no notify at all (it notifies only while there is exactly one), so the new wrapper never goes weak and the GObject is immortal. Retiring it means NOT severing the link: keep the record as a TOMBSTONE once the net has fired (never freed, so qdata may keep naming it) and let a re-wrap ADOPT its orphaned toggle ref. Shape + the rejected `ref_count` discriminator: open-todos.
|L2 SHIPPED: **`gjsGiNodePlugin`** — `--app node` rewrites `gi://Ns?version=X` → a virtual module `export default requireGi('Ns','X')` from `@gjsify/node-gi/gi`, kept EXTERNAL (native addon). **`@girs/*` value-import routing gated on `nodeGiGlobalsInject`**: by default `@girs/*` → empty (cross-platform node bundles stay node-gi-free + loadable on plain Node); for a genuine GJS source built via the reverse bridge, `emptyGirs:false` lets `@girs/adw-1` resolve to its real body so the inner `gi://` gets rewritten — fixing `class extends {} → "Class extends undefined"` (the Adwaita-storybook-on-node wall). Proper-cased namespace comes from the @girs package's own `gi://` specifier (no name map). e2e `node-gi-build` + `node-gi-girs-resolve`. **Ambient-globals injection SHIPPED**: `--app node` auto-injects a side-effect `import '@gjsify/node-gi/globals'` when the GJS ambient globals (`print`/`imports`/`ARGV`/…) survive in the bundled, tree-shaken output — ONE analysis pass (`detectNodeGiGlobals`; the shim is external, adds no bundled code). Injection is CONDITIONAL on real post-tree-shake detection (the #1 regression risk: eager import loads the native addon on plain Node); the detector flags BARE identifiers only, NOT `globalThis.imports`/`globalThis.print` — the cross-platform isomorphic-guard shape must not trigger injection. e2e `node-gi-globals-inject`. **Bare built-ins** (`system`/`gettext`/`cairo`): `ALIASES_GJS_FOR_NODE` is filled and `app/node.ts`'s `NODE_GI_BARE_MODULE_SPECIFIERS` is DERIVED from its values so they can't drift — load-bearing because `@gjsify/rolldown-native` drops the resolveId `external` flag at its JSON boundary, so only the `exactExternal` string array survives (cairo missing there broke canvas2d on the GJS bundler while npm rolldown hid the gap). Unit `node-gi-externals.spec.ts`.
|mainloop: **SHIPPED, both directions** (`src/loop.cc`, N-API port of node-gtk's `loop.cc` + an original uv-driven auto-pump) — (a) blocking case: a `GSource` polls libuv's backend fd + runs `uv_run(NOWAIT)` on dispatch, so `Gio.Application.run()`/`GLib.MainLoop.run()` BLOCKS like GJS yet keeps Node timers/I/O alive; (b) NON-blocking case (the consumer-survey P1 fix): a uv_prepare/uv_check pair drains ready GLib sources each libuv turn, a mirrored uv_timer + uv_poll watchers on the context's queried fds (incl. its cross-thread wakeup eventfd) wake libuv for GLib timers/GTask completions, and a `process.on('beforeExit')` kick re-arms an otherwise-empty loop — so a plain `node bundle.mjs` awaiting Gio async work drains WITHOUT any explicit loop, byte-identical to `gjs -m` (conformance `async-gio-await`; ledgered for bun/deno, which keep `startMainContextPump`). **`system.exit` is TERMINAL and must never route through `globalThis.process`** — `system.js` binds the RUNTIME's own process ONCE at module evaluation (`getBuiltinModule('node:process')` first, the module-eval capture as fallback). A bundle that registers `@gjsify/node-globals/register` replaces `globalThis.process` with the `@gjsify/process` polyfill, whose `exit()` delegates BACK into `imports.system.exit` through a GLib idle whenever it sees one; reading the global closed that into an infinite idle-driven recursion which ran `@gjsify/node-globals`' 221-test suite green and then spun at 100 % CPU forever. Byte-compared against gjs by conformance `system-exit-lifetime`. Keep-alive counts **JS-armed GLib work only**, identically on node/bun/deno: a GI callback the program handed to GLib and GLib has not dropped yet — a scope=async completion, or a scope=notified source (`GLib.timeout_add`/`idle_add`, released on its GDestroyNotify). A REPEATING timeout armed FROM JS therefore has `setInterval` semantics (the one lifetime divergence vs gjs, which exits when the module settles); a timer armed inside a C library does NOT hold the process, and a sync-only program exits immediately. That distinction is load-bearing: keying the hold on "the context has ANY scheduled source" immortalizes a finished GTK program, because GDK keeps a ~1 s repeating timeout armed for the process's whole life — the context then reports work forever while nothing is ever ready to dispatch. On the uv side wake-up and hold are separate decisions: the mirrored uv_timer is armed for every GLib deadline, ref'd only while the program's own GLib work is outstanding. Bun/Deno get the same contract from the portable pump, which `requireGi` auto-arms (the twin of `native.startMainLoop()`) with its timer starting UNREF'd and ref'd off the JS-armed counter, plus a `beforeExit` beat backstop; leaving it opt-in + permanently unref'd is what made ONE bundle exit 0 MID-flight on bun/deno while node ran it to completion. The auto-pump's beat DISPATCHES on the same counter it holds on (explicit `startMainContextPump()` callers keep unconditional dispatch), and its idle path makes ZERO napi calls — it reads the counter through the external `pumpPendingCount` Int32Array view, because on Deno merely ENTERING the addon from a timer tick during the between-test-files GC window reproduces the #47 boxed-handle teardown SIGSEGV (measured on the gtk-smoke leg: full dispatching tick 139 10/10, query-only tick 139 3/3, addon-silent tick exit 0; with the view-gated beat 10/10 exit 0). Guards: pump callbacks no-op at `g_main_depth() > 0` (no double-dispatch under a blocking run) and the UvLoopSource is parked during pump-driven iterations (no reentrant `uv_run`), while every C→JS dispatch clears the parking flag (`NodeGiPumpJsDispatchScope`) so a blocking run started from a dispatched callback still co-pumps. **The wake-up HINT pass closes its own GLib cycle** — `prepare`+`query`+`check` (revents 0), never prepare+query: a GSource may hold a LOCK across that pair, and GDK's Wayland source does (`prepare` takes libwayland's reader slot, only `check` returns it), so a query-only pass left it held and the next `gtk_window_present()` blocked forever in `wl_display_roundtrip` — a live process whose GDBus worker still answered Ping/Introspect while every devtools method timed out, read for a whole matrix as "devtools hangs" (#1145). Wayland-only, node-only, and only once GTK was initialised at `g_main_depth() == 0` (`register()` before `runAsync()`). Guarded by `test/wayland-prepare-check.test.mjs` under headless weston in `gtk-smoke`; every other GTK leg pins `GDK_BACKEND=x11`. `startMainLoop()` (idempotent, arms both) is auto-called by `requireGi` on first namespace load — no manual call needed. Includes the **boxed/struct slice** the loop needs: `GLib.MainLoop.new`→a tag-distinct boxed handle (`callBoxedMethod`/`isBoxedHandle`, `g_boxed_free` on GC for owned)→`.run()`/`.quit()`, `JsToGIArgument`/`GIArgumentToJs` struct in/out + null-pointer for nullable interface args. CAVEAT (node-gtk #442/#121): promise continuations queued before a blocking `run()` nested inside an outer async scope (node:test, await, a signal handler) don't drain until `run()` returns — V8 refuses a nested microtask checkpoint; `process._tickCallback` (nextTick) + timers/I/O are fine. L1 fix (defer the run to a macrotask when a checkpoint is in progress) is a later step

|**a STAGED prebuild SHADOWS your local build**: `nativeCandidates()` returns `[prebuild, release, debug]`, so after `node-gyp build` a bare `node probe.mjs` still loads `prebuilds/<target>/node_gi.node` and your C++ change appears to do nothing — measured while landing the struct-field array-length fix, where a working fix read as a failed one.
