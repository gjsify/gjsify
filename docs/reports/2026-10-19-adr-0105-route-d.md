# ADR 0105 § 2 route D: `registerClass` over a NativeScript parent class

Date 2026-10-19. Verdict: **yes. The widget can be a real GObject subclass with no consumer-visible
change, and the twin can go on NativeScript Android.**

## Question

The [inversion spike](2026-10-18-adr-0105-inversion-spike.md) failed on one sentence:
`registerClass` refuses a `View` base, so the GObject chain and the widget chain cannot merge, and
layout only accepts the unwrap `widget.view`. Route D asks the other half of that sentence: what
if the JS object stays the real `@nativescript/core` widget, and the GObject is ATTACHED to it
rather than the object being made into one?

"Works" meant all of, with **zero `.view` unwraps at any consumer call site**:

1. an instance is `instanceof` its host class, `View`, `ViewBase` AND `GObject.Object`;
2. a layout takes the widget itself and renders it;
3. a declared GObject property notifies and can drive a host property; `bind_property` both ways;
4. a registered signal connects and emits, with NativeScript's own events intact beside it;
5. identity through C — `Gio.ListStore` append/get_item returns the same JS object;
6. lifetime: a removed widget and its native view are finalized, a live one is not;
7. the cost against the twin.

## Step 0: there is nothing upstream to mirror

100 GJS commits landed between this checkout's `refs/gjs` (`caea4931`, 2026-07-06) and 2026-10-17.
Three mention classes at all and none touches `registerClass`, custom parents or mixins. GJS still
hard-throws `GObject.registerClass() used with invalid base class (is …)` unless
`klass.prototype instanceof GObject.Object | GObject.Interface`
(`refs/gjs/modules/core/overrides/GObject.js:54-58`). Route D is therefore our own extension, not a
port of someone else's.

## The exception, and how it is gated

The owner's decision on 2026-10-19: this is an allowed divergence from GJS, because on NativeScript
**only node-gi ever runs** — GJS is not a target on Android — and it is the host's hard
`instanceof ViewBase` gate that forces the question. Two conditions came with it, and both are met:

- **Gated on the host.** `FOREIGN_PARENT_CLASSES` in `packages/node-gi/node-gi/host.nativescript.js`
  (`true`) and `host.node.js` (`false`), the same `#host` export-condition mechanism as
  `LAZY_NATIVE`. On every other host `registerClass` still throws node-gi's stand-in for GJS's
  invalid-base error, and a class registered there gets no `$foreignSkipped` own property — the
  static surface off NativeScript is byte-for-byte what it was.
- **Documented as deliberate** in `docs/node-gi-gjs-surface.md` (its own subsection under
  `registerClass`), ADR 0105 § 2, `packages/node-gi/AGENTS.md` and
  `packages/node-gi/node-gi/README.md`.

Both sides of the gate are asserted directly in
`packages/node-gi/node-gi/test/foreign-parent.test.mjs`, not only through their consequences.

## Method

The whole route lives in `gi.js`; no native change was needed, and the addon was rebuilt only to
carry a fresh payload. Registration, attach, notify, signals and identity are covered against a
real GObject on the desktop by `test/foreign-parent.test.mjs` (12 cases), which reaches the
NativeScript host by handing it the loader name it looks for. The half only a device can answer —
layout, rendering, NativeScript's event system, lifetime under the V8/Java runtime, and the cost —
is `tests/integration/nativescript-gi/app/specs/foreign-parent.ts`.

Devices: an API 36 x86_64 emulator and a Samsung SM-G960F (`starlte`, arm64-v8a, Android 10). Both
ran **123 of 123 cases green** with the bench on. The Gtk typelib is not in the AAR, so the subject
is a `Label` subclass with a `caption` string property and an `activated` signal; the question is
about NativeScript's side of the door. Benchmark method as in
[the gates report](2026-10-15-adr-0110-gates.md): 4000 ops, 2 warm-up rounds, 7 interleaved rounds,
median.

## How it works

- The registered GType is rooted at **`GObject.Object`**. The foreign parent contributes no GType
  at all, so the GObject hierarchy and the JS prototype chain are two independent trees. That is
  the whole trick: nothing has to merge.
- The GObject is **attached, never wrapped**. No construct-trap Proxy, no `Object.setPrototypeOf`:
  the handle is a lazily-attaching prototype getter, so `instanceof GObject.Object`, argument
  unwrapping and every installed member force the attach on first touch. The object's
  `[[Prototype]]` stays exactly what `@nativescript/core` built, which is what its hard
  `instanceof` gate needs, and the user class's constructor body runs because it is the host's own.
- Identity and lifetime come for free: the instance cache is a `WeakMap` keyed by the canonical
  handle, so a round trip through C returns the same JS object.
- A spelling the host chain already owns is **left alone** rather than shadowed, and the skipped
  names are readable as `MyClass.$foreignSkipped` (frozen, defined on every registration under this
  host). On a `Label` subclass that list is `[setProperty]`.
- **`notify` is the one real collision in the `Label` chain** (`Observable.prototype.notify`) and
  is resolved by argument type: a string is GObject's `notify(prop)`, anything else is forwarded to
  the host implementation captured before the definition is installed. `disconnect` is not a
  collision — in `@nativescript/core` it exists only on `GesturesObserver`.
- **`vfunc_*` overrides are deliberately not supported** on this path: they would need the instance
  prototype re-linked, which is the one thing route D must not do.

## Results

Same on emulator and S9 unless a row says otherwise.

| Criterion | Result |
|---|---|
| 1. both worlds | `instanceof Label`, `View`, `ViewBase` and `GObject.Object` all true; `GObject.type_name($gtype)` is the declared name; the host half untouched (`w.text` still works) |
| 2. layout | `stack.addChild(w)` takes the WIDGET, `getChildAt(0) === w`, `w.parent === stack`, `removeChild` clears it. A registered `StackLayout` subclass accepts children including another registered widget. Mounted into the page's `GridLayout` and rendered on both devices (screenshots) |
| 3. property | `notify::caption` fires for `w.caption =` and `w['caption'] =`, drives `Label.text`, and GJS's equal-value guard holds (a repeat set emits nothing). `bind_property` BIDIRECTIONAL both ways, and `unbind` really unbinds |
| 4. events | `connect`/`emit`/`disconnect` of the registered `activated` signal work. On ONE object: `on('custom')` + `notify({eventName})` = 1, `notify('caption')` = 1 `notify::`, `emit('activated')` = 1 — and `hasListeners` is unchanged by any of it. A **real** `MotionEvent` DOWN/UP pair through `View.handleGestureTouch` fires the `on('tap')` handler on the mounted widget, which writes the GObject property, whose `notify` carries it to `Label.text` |
| 5. identity | `Gio.ListStore` append then `get_item` returns the same JS object, still a `Label`, host state intact |
| 6. lifetime | removed widget finalized; a widget held only through a `ListStore` finalized once the store releases it (the toggle-ref path); a live widget NOT collected early; a store-held widget keeps identity and host state across gc. **Exception below** |
| 7. cost | below |

### Criterion 4's one surprise, and it is NativeScript's

`on('tap')` does **not** go through `Observable`. `View.addEventListener` coerces a gesture name and
sends the listener to a `GesturesObserver` instead, so `hasListeners('tap')` is false and
`notify({ eventName: 'tap' })` reaches nothing — **on a plain `Label` exactly as on a route-D
widget**. The spec's first draft asserted the Observable behaviour for `tap` and failed twice for
that reason; it now asserts parity with a plain `Label` control for the registration, and drives
the gesture for real. Nothing about route D was involved.

### The leak, unchanged

A signal handler closure that captures an enclosing `this` is **never collected** — `finalized=false`
on both devices, the same C-JS closure cycle the 2026-10-18 spike found. A handler that reads the
emitter it is handed is collected normally. This now reaches widgets, so the per-widget migration
must use the emitter argument. It is a node-gi defect, not a route-D one, and it is unfixed.

## Benchmark, route D versus the twin

Median ns/op, 4000 ops x 7 interleaved rounds. "Bare" is the registered property alone; "wired"
also drives `Label.text` from a `notify::` handler, which is what a real widget does.

| | route D bare | route D wired | route D emit | twin set+notify | twin emit | host `Label.text` |
|---|---|---|---|---|---|---|
| emulator (x86_64) | 6289–8907 | 9881–10319 | 1791–1805 | 10100–10587 | 3501–4451 | 114–130 |
| S9 (arm64-v8a) | 40445 | 58171 | 12879 | 60614 | 23212 | 372 |

Ratio twin/route-D on the S9: **1.50x** on set+notify, **1.80x** on emit. The emulator spans two
runs and is noisy (1.19x–1.61x, 1.94x–2.48x); the S9 numbers are the stable ones. Route D is
slightly faster than the inversion spike measured in the same runs, but the honest reading is that
both sit inside the same ~20-30x gap against pure JS (same S9 run: real-gio/pure-js set+notify
24.46x, emit 30.75x). **The case for route D is the API, not the clock**: the twin disappears and
no call site changes.

## Incident found on the way: a `\p{L}` regex literal breaks the whole bundle

Not part of this spike, fixed at the core because it is a live break on `main`.
`packages/web/adwaita-core/src/release-notes.ts` carried `/^\p{L}$/u` as a regex **literal**,
landed in `6c88ac780b`. V8 validates regex literals at PARSE time, and NativeScript's Android V8 is
built without i18n, so the module — and with it the entire bundle — died before its first line:

```
Cannot compile ES module /data/data/org.gjsify.NsGiTest/files/app/bundle.mjs
SyntaxError: Invalid regular expression: /^\p{L}$/u: Invalid property name
```

Fixed by building the same regex once at runtime with `new RegExp('^\\p{L}$', 'u')` inside a `try`,
with a table-free fallback (XML 1.0 `NameStartChar` above ASCII plus `ª`, `µ`, `º`). Measured over
all 1,111,936 non-ASCII code points the fallback rejects **zero** real letters and over-admits
5,022 of the 63,360 non-ASCII BMP points — deliberately the permissive direction for a name
validator.

**Follow-up (closed by #2302):** the runtime regex and its fallback gave way to `GLib.unichar_isalpha`,
answered from a generated `L*` range table (`scripts/generate-glib-unichar.mjs`), and
`scripts/check-nativescript-no-icu-regex.mjs` now rejects ICU-only constructs in every
NativeScript-shipped source.

## Decision input

Route D meets every criterion with no consumer-visible API change, on both ABIs. It costs one
gated divergence from GJS, invisible off NativeScript and documented in three places, and it gives
up `vfunc_*` on foreign-parent classes. ADR 0105's "the twin stays permanently" is superseded for
the NativeScript Android port; the migration is per widget, behind the engine interface that
already hides the twin.
