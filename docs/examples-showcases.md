# Examples and showcases

> Detail for the root [AGENTS.md](../AGENTS.md).
> `examples/` is private dev/test, `showcases/` is published.

## Example convention (GTK + browser)

Dual-target with Adwaita UI: `examples/gtk/<name>/src/` = shared platform-agnostic `.ts` (constants/logic — both targets import; no duplication in HTML) + `gjs/` (Adw.Application, .blp) + `browser/` (adwaita-web UI, index.html) + `assets/`. Scripts: `build:gjs`→`gjsify build src/gjs/gjs.ts --app gjs` | `build:browser` | `start`→`gjsify run dist/gjs.js` | `start:browser`. NO explicit `/register` imports in example/showcase source (§ Tree-shakeable globals rule 6 — use `--globals auto,<extra>` in the build script if auto misses). `examples/` = `"private":true`, not published, not in the CLI.

## Showcase — `gjsify showcase`

Polished examples under `showcases/`, published as `@gjsify/example-{dom,node}-<name>`, CLI deps, self-contained + independently runnable (`gjsify showcase <name>`; production-quality, not experiments; browser entry embeddable by the website via package exports — never internal relative paths). Assets via `require.resolve('@gjsify/example-dom-<name>/assets/<file>')`; exports pattern: `./browser`, feature modules, `./assets/*`, `./package.json`.

**Runtime selector — `--runtime <gjs|node|bun|deno>`** (shared `utils/runtimes.ts`; the node-gi `example/harness.mjs` keeps its OWN copy on purpose — a standalone published consumer must not import CLI internals; keep in sync). gjs → `--app gjs` bundle via `runGjsBundle`; node/bun/deno → the SAME `--app node` bundle (`runRuntimeBundle`; deno runs `--node-modules-dir=manual`). `@gjsify/node-gi` is resolved from the BUNDLE's own directory first, cwd fallback (`resolveNodeGiForBundle` — node-gi stays external and the runtime resolves the bare specifier relative to the importing FILE; a cwd-only probe refused dlx-cache runs). **`showcase`'s default runtime is `gjs` whenever gjs is installed, else the host** (`defaultExampleRuntime()`): a showcase's canonical artifact is its `--app gjs` bundle, so following the host made `npx @gjsify/cli showcase <name>` ask for a node bundle that doesn't exist. `gjsify run` answers the same question by sniffing (`isLikelyGjsBundle`); `storybook` keeps the plain host default (it BUILDS what it launches). `--runtime` on `run` forces file mode.
|**per-showcase declaration `gjsify.example.runtimes: ["gjs","node","bun","deno"]`** (optional; omitted = permissive): an undeclared requested runtime is a clean error, not a crash. **The declaration describes SHIPPED artifacts, so it must agree with the `build` script** — declaring `node` means `build` runs `build:node` and `files` ships it (two showcases shipped "declared node entry not found" because their `build` never called their `build:node`); no node bundle ⇒ declare `["gjs"]`. MACHINE-CHECKED: `package-outputs` claims `gjsify.main` + `gjsify.example` (declared node entry must exist; a declared non-gjs runtime must have the derived `dist/<name>.node.mjs`); showcases are checked by a second sweep (`verify-package-outputs.mjs --scope examples`) after `Build examples` in CI and after `build:examples` in `npm:publish`. The non-gjs path installs `@gjsify/node-gi` INTO the dlx tree (`ensurePkgDir({extraSpecs})`, part of the cache key) — the bridge is a devDependency, so a dlx tree never had it. NB `gjsify.example.runtimes` ≠ `gjsify.runtimes` (§ Runtime & platform model).
|**dep rule:** bundled deps → `devDependencies`; ONLY packages whose native prebuilds `gjsify run` needs at runtime stay `dependencies` (today: `@gjsify/webgl`) — the general form: every typelib-owning package a consumer RUNS must be a runtime dependency (build-time inclusion ships no typelib).
|adding: `showcases/{dom,node}/<name>/` + `"files":["dist"]`, no `"private"` → export browser entry/assets/package.json → add an entry to `packages/infra/cli/showcases.json`. **Discovery reads THAT manifest** (`utils/discover-showcases.ts`) and `gjsify showcase <name>` delegates to `gjsify dlx <package>` — a showcase is deliberately NOT a CLI dependency, so adding one needs no CLI rebuild and does not grow the CLI tarball. Dropping `"private"` publishes a NEW npm name, so `gjsify onboard` must run for it BEFORE the release that ships it (§ New `@gjsify/*` package) — an unbootstrapped name 404s the OIDC exchange and stalls every alphabetically-later package. Website side: a `@gjsify/website` dependency, a name in `SHOWCASE_NAMES` + a mounter in `SHOWCASE_MOUNTS` (`website/src/components/showcase-registry.ts` / `showcase-mounts.ts` — `SHOWCASE_DEFAULT_OPTS` too when it loads assets, matching the copy list in `website/scripts/copy-showcase-assets.mjs`), a row in `website/src/content/docs/showcases/index.mdx` + its own page beside it, and — only if it should appear on the LANDING page — a slide in `components/ShowcaseSlideshow.astro`; the catalog alone does not put it there. This list used to name a `switch` arm per host component, and the LDraw showcase shipped a landing-page slide with no arm behind it: the slide rendered, the demo frame stayed empty, nothing failed. The two switches are now one registry, `SHOWCASE_MOUNTS` is `Record<ShowcaseName, …>` so a name without a mounter does not type-check, and the slideshow throws at build on an interactive slide that names something unmountable.
|`showcases/gtk/*` — native GTK/Adwaita showcases (platform demos, not DOM polyfill demos). First: `@gjsify/example-gtk-adwaita-storybook`, launched by `gjsify storybook` NOT `gjsify showcase` (so not a CLI dep); `"private": true` + versioned (publish loop skips private); workspace member so CI type-checks it.
