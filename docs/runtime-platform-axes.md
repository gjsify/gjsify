# Runtime & platform axes — enforcement and strategy

> Detail for the root [AGENTS.md](../AGENTS.md) § Runtime & platform model, which
> defines the four axes and stays authoritative for the model itself. This file holds
> the OS-axis enforcement invariants and the portability strategy behind them.

### OS axis enforcement — declared vs built vs loadable

`scripts/audit-runtimes.mjs --check` holds, per native package:
|three DECLARATION invariants: a committed `prebuilds/<target>/` is declared · a declared target is produced by a CI job · a pkg shipping prebuilds has a workflow that reproduces them (a hand-built binary nothing rebuilds drifts from its sources in silence). Declared-vs-built is symmetric — changing CI forces changing the declaration and vice versa. `--platforms` renders the OS × package matrix (`--markdown` for a terminal or a paste; the website's Platform Support page renders from `platformMatrixData()`, the shared function both go through, via `website/scripts/generate-platform-matrix.mjs` — a hand-pasted copy of the rendered table lived on that page and drifted twice, latterly to `·` for `@gjsify/webgl` on win32-x64, the one cell a Windows reader opens it to check) — one row per BRIDGE, and its glyph legend is machine-checked (`tests/e2e/ci-runner-arch`): `✓` = the artifact is committed HERE, which since ADR 0017 means in the bridge's per-target package, so the row is credited from its children (`creditPlatformArtifacts`, the mirror of `creditPlatformPackages`) BEFORE they are filtered out of the table; `○` = declared and CI-built but nothing committed here, i.e. a `platformsUncommitted` deferral OR an install-time bridge. A cell reading `shipped`/`platformsUncommitted` off the bridge is structurally blind after the split (both are always empty there) and printed `✓` "artifact committed" for `@gjsify/napi` + `@gjsify/node-gi`, which commit nothing — a reporting path cannot exit non-zero, so the glyph needs its own test. **These three compare declarations to EACH OTHER, so all stay green on a promise with nothing behind it** — a target with no directory is simply absent from the compared "shipped" set, which is how `@gjsify/oxfmt-native` declared `darwin-arm64` with no artifact for weeks. Hence:
|the prebuild-ARTIFACT invariant: for every pkg naming a committed `gjsify.prebuilds` dir, each declared target is OPENED. (1) EXISTENCE: `prebuilds/<target>/` exists and holds a shared library in that OS's format (`.so`/`.dylib`/`.dll`), the `.typelib` without which `GI_TYPELIB_PATH` resolves nothing, and the `.gir` it was compiled from. **The `.gir` is the one of the three that is NOT runtime-critical, and the check says so**: nothing loads a `.gir` (girepository resolves the typelib; no path in `detectNativePackages()`/`buildNativeEnv()` opens one), what breaks is everything downstream of the committed artifact — six bridges' `build:gir-types` point `ts-for-gir --girDirectories` straight at `<bridge>-linux-x64/prebuilds/linux-x64`, and the darwin `shared-library`-leaf assertion parses the GIR. It is a HARD failure anyway, on PROVENANCE: `stage-prebuild.mjs` matches `.gir` by extension, so every directory the stager wrote has one and a directory without one was written by something else. Its escape is the caller-injected `prebuildGirGaps` map (package → reason, mandatory reason, printed every run, FAILURE the moment the file lands) — a caller option rather than a manifest field because the manifests it would sit in are GENERATED from derived fields only. **Nothing injects one today, and there is no ledger module to**: all ten directories that were in it received their `.gir` through `commit-prebuilds` rather than by hand, which is the proof the channel works, so the drained module was deleted — and `stage-prebuild.mjs` refusing a `.typelib` with no `.gir` beside it closes the class structurally rather than draining it once. The option, `scripts/clear-satisfied-gir-gaps.mjs` and the arrival check in `platforms-ci` survive as the mechanism a future gap gets recorded and auto-retired through; restaging, not recording, is the answer to a `.gir` missing today. (2) LOADABILITY, because a directory that exists proves nothing (#832: a required macOS job built two bridges and only COPIED them; the bug was a missing sibling FILE reading exactly like a broken rpath) — STRUCTURALLY on every artifact regardless of target (the image's own machine matches its directory; every `libgjsify*` sibling staged + reachable via `$ORIGIN`/`@loader_path` per the shared `binary.mjs` parser; every library leaf the TYPELIB records present, since that leaf is what GI hands to `dlopen`), and FUNCTIONALLY — a real env-free `dlopen` — only for the checking host's OWN `${process.platform}-${process.arch}`. A cross-arch prebuild CANNOT be loaded on a Linux runner and the audit does not pretend otherwise: both counts are printed separately every run, and a bridge whose SYSTEM deps the runner lacks is reported as not-load-tested, never as broken. The ONE binary parser (Mach-O/ELF/PE + GI typelib) lives in `@gjsify/manifest-conformance` `lib/binary.mjs`, re-exported by `scripts/check-prebuild-loader-path.mjs` — extend it, never add a second.
|escape hatch `gjsify.platformsUncommitted: {"<target>": "<why>"}` — declared AND CI-built but deliberately not committed here. Deliberately awkward to abuse: the reason is mandatory and PRINTED every run (`audit-runtimes --check` lists the live set — do NOT restate it here, the copy that did went wrong the next time a target was added), the target must already be in `gjsify.platforms` (you can only defer what you promise), and the entry becomes a FAILURE the moment the directory appears. An honest "not shipped here" is available; a silent gap is not.
|**two kinds of exemption, and only one retires itself.** TEMPORARY: the producing leg is in `prebuilds.yml`, so `commit-prebuilds` will land the directory and `scripts/clear-committed-platform-exemptions.mjs` (wired into that job) deletes the entry in the SAME commit that adds the artifact. PERMANENT: no job commits the artifact into this repo at all, so the entry is the standing truth — `@gjsify/napi`, BOTH targets. Its prebuilds are built three times over (`napi.yml` rebuilds and gates on them; `release.yml`'s `napi-prebuild-*` legs rebuild from the released tag and `publish-napi` stages the download into the per-target package) and committed by nobody. **A committed copy for ONE of a bridge's targets is the shape to avoid**: `packages/napi/napi-linux-x64/prebuilds/` was tracked while its darwin sibling was exempt, so the same bridge ran two policies, every job that touches the path overwrote the checked-out bytes before reading them, and the three declaration invariants stayed green across a week of source drift because they compare declarations to each other. Deleting it made the asymmetry go away and freshness real by removal — the only linux-x64 artifact anyone can load is now one CI just built.
|**the RELEASE-COVERAGE invariant — "a CI job builds it" is not "a consumer receives it".** The three declaration invariants read the UNION of `prebuilds.yml`+`napi.yml`+`node-gi.yml`+`release.yml`, which answers *does CI build this* and deliberately says nothing about who SHIPS it. For a target whose artifact is committed here that is the whole story (the ordinary `publish` job packs the checked-out directory); for a target this repo commits NOTHING for, the only way one reaches a consumer is inside the tarball a `release.yml` job stages — an artifact belongs to the run that produced it, so a release cannot download another workflow's upload. So `releaseOnlyTargets()`/`auditReleaseCoverage()` (`platforms-ci`) ask `release.yml` ALONE, per ownership: `install-time` ⇒ every declared target needs a release leg (`@gjsify/node-gi`) · `committed-here` ⇒ only its `platformsUncommitted` targets (`@gjsify/napi`'s two per-target packages, whose exemption reasons name those legs) · `split` ⇒ skipped, each child answers for its own target. Targets `prebuilds.yml` builds are SUBTRACTED — that is the TEMPORARY exemption above, on its way to being committed, and demanding a release leg for one would block every new exotic-arch addition. Written because the same gap shipped TWICE: 0.26.0 published `prebuilds/linux-*` only while `win32-x64`+`darwin-arm64` were declared and green in the union, and #921 re-opened it the same day it added `darwin-x64` (declared, a node-gi.yml matrix leg, no release leg) — where the next release would have failed `publish-node-gi`'s manifest-derived staging assertion and dropped `@gjsify/node-gi` from that release entirely. A promise that no job SHIPS is the gap; the union cannot see it.
|CI parsing: `parseCiPlatforms()` reads `prebuilds.yml`'s matrix as STATIC YAML (job `runs-on` → OS, `arch:` entries filtered to tokens that actually name a CPU, so an `arch:` that is an ACTION INPUT cannot become a phantom `linux-none` target) — an expression-driven matrix hides the arch tokens and fails all ten native packages; teach the parser first if it ever has to become dynamic. A target is attributed to a package when a STEP names the package AND carries a production verb — moving a build script into a file is safe, deleting the per-package upload steps is not.

### Strategy & portability portfolio

GJS = primary target, NON-NEGOTIABLE. Long-term: "alles unter allem lauffähig" — share what's shareable across GJS / Node / browser / NativeScript; runtime-specific where not. **Opportunistic, not driven**: existing GJS-bound packages stay GJS-only (no refactor budget; NO "while-I'm-here" scope creep in bug-fix PRs); NEW packages whose impl is pure-TS-portable get cross-runtime treatment from day one; GJS remains the test driver for everything (the only runtime where all three pillars need polyfill). **"Opportunistic, not driven" scopes the RUNTIME axis ONLY — the OS axis is DRIVEN** (ADR 0018, accepted 2026-08-06): Linux + macOS + Windows are a project goal, so `linux-{x64,arm64}` / `darwin-{x64,arm64}` / `win32-x64` are the target set and a package that BRANCHES on the OS owes a declared, checked claim about all three. Reading the runtime clause as covering operating systems is exactly how the whole native-bridge set stayed Linux-only while the project described itself as platform-independent; measured 2026-08-05, 10 of the 16 packages whose own source branches on the OS declared no OS axis at all, while 74 packages declared `gjsify.platforms` — the axis was declared where a BINARY exists and absent where a DECISION is made. CLOSED by the `os-axis` rule: `gjsify.os` + `gjsify.osNotes` are held by `@gjsify/manifest-conformance` on every `audit-runtimes --check`, the candidate set is DERIVED from shipping source (a spec that branches on the OS is `it.failing(…, {when})`'s job, not a support claim — which is why the nine are `cli`, `utils`, `rolldown-plugin-gjsify`, `devtools`, `child_process`, `os`, `process`, `util` and the express showcase rather than the ADR's original ten), and every claim below `supported` prints its mandatory reason on each run.
|the six axes: **1** Node-API (`packages/node/*`) · **2** Web-API (`packages/web/*`) · **3** DOM (`packages/dom/*`) · **4** design-identity — carry a runtime's design system to OTHER runtimes: `@gjsify/adwaita-{web,fonts,icons}` → browser, `@gjsify/adwaita-nativescript` → real NS widgets, shared behavior lifted into headless `@gjsify/adwaita-core` (ADR 0004) · **5** platform-bridge — carry a runtime's NATIVE platform to OTHER runtimes: `@gjsify/iframe`/WebKit precedent; ACTIVE tracks node-gi + napi (§ Cross-runtime tracks); GTK-on-browser stays a non-goal (design-identity is the right tool) · **6** bundled toolchains (§ Cross-runtime tracks).
|**new-package convention — the runtime axis is the FIRST clarification question**: (a) `gi://`/`@girs/*` value-imports → GJS-only (`runtimes.{node,browser}:"none"`); (b) pure TS, no platform-native deps → all-`polyfill` from day one, tested on all runtimes; (c) native runtime equivalent exists → declare `"native"` for that slot, ship `<pkg>/globals` (Node) or browser-conditional export. Canonical exemplars to mirror (package.json + `src/test.{mts,browser.mts}` layout): `@gjsify/dom-events` (`{gjs:polyfill,node:polyfill,browser:native,nativescript:native}`); `@gjsify/abort-controller`/`@gjsify/dom-exception` (same but `node:native` + `globals.mjs`).
|`@gjsify/utils` split (ADR 0014): `@gjsify/utils/core` = the cross-runtime half (pure + GJS-guarded: `makeCallable`, `deferEmit`, `initErrorV8Methods`, `gio-errors` errno map, `registerGlobal`, `notImplemented`/`warnNotImplemented`, `queueMicrotask`, `structuredClone`, `nextTick`, `ensureMainLoop`/`quitMainLoop`); the barrel adds the six GJS-only modules (`byte-array`, `cli`, `file`, `fs`, `gio`, `path`). A package whose `browser`/`nativescript` slot is `polyfill`/`partial` MUST import `/core` — importing the barrel is a DECLARATION that it reaches GLib/Gio; `audit-runtimes --check` enforces it. Split on measured imports, never on module name (`gio-errors.ts` is pure despite the name).
|universal `-core` split (convention, not mandate): logic shared by ≥3 runtimes MAY split into platform-agnostic core + thin adapters — but a `/core` SUBPATH is the DEFAULT over a new `-core` PACKAGE: a new published `@gjsify/*` name needs a tier, a quintuplet and the manual first-publish + Trusted-Publisher bootstrap (§ Package convention), and skipping that breaks the serialized release train for every alphabetically-later package. A separate package only for a genuine cycle or independent external consumers (`@gjsify/canvas2d-core`).
|**graduation** (2026-05-28): axes 1–4 are OUT of experimental status — document them per-axis, and describe what is validated BY NAME (integration suites, Playwright browser tests, autobahn, named showcases); never blanket "WinterCG-compatible"/"Node-compatible runtime" claims. Axis 5 pre-graduation. The per-package slot tables + audit drift are derived from the manifests, which are the single source of truth.
|non-goals: turning gjsify into a runtime; replacing Node/browser-native APIs where they exist; spec conformance beyond what a correct polyfill needs; tracking `refs/node-gtk` as a live fork (read-only derivation source); refactoring existing GJS-bound packages cross-runtime.
