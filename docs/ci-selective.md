# Selective CI — affected-only test runs

> Detail for the root [AGENTS.md](../AGENTS.md) and [tests/AGENTS.md](../tests/AGENTS.md).
> How CI decides which suites a change actually needs.

### Selective CI — affected-only test runs

CI's `linux` job is gated by `gjsify affected` (diff vs PR base → which tiers run). The `changes` job boots a **dedicated committed classifier bundle** `packages/infra/cli/dist/affected.gjs.mjs` on plain ubuntu+gjs — NOT the full CLI bundle, which eagerly imports `gi://Soup` (via npm-registry→fetch) that the classifier host lacks; booting it there crashed → `continue-on-error` failed OPEN to a full run on every PR (the silent regression the split fixed). The dedicated bundle pulls only GLib/Gio/GioUnix. Guarded by `tests/e2e/affected-classifier-bundle`; the pre-commit hook rebuilds it too. **Place new tests where the classifier finds them:** spec files `<workspace>/src/**/*.spec.ts` (seed = that workspace, no closure expansion); integration suites `tests/integration/<name>/` declare every exercised pillar in `dependencies` (the forward-graph walk fires the tier); e2e `tests/e2e/<name>/` runs only when `tests/e2e/**` is touched or on a global trigger — no per-workspace functional tests there; browser `tests/browser/specs/`.

**Closure model — PRODUCTION deps only.** The reverse-dependency closure walks `dependencies`/`optionalDependencies`, NOT `devDependencies` (`includeDev: false`): a test re-runs for a RUNTIME relationship; devDep edges are the toolchain, and with the umbrella polyfill metas they fanned any single change out to ~210 of 221 workspaces. Consequence: **a package's spec must not import a cross-package sibling it declares only as a devDependency** — that edge is invisible to the closure. The integration forward walk stays `includeDev: true` (over-running is cheap). Backstop: push-to-main + nightly run the FULL suite.

**Global triggers** (force full run): `packages/infra/{workspace,cli,rolldown-plugin-gjsify,resolve-npm}/**`, `packages/gjs/unit/**` (the test framework every spec imports — a devDep, so the prod-only closure can't reach its consumers), `gjsify-lock.json`, root `package.json`/`tsconfig*`, `scripts/audit-runtimes.mjs`, `.github/workflows/main.yml`. **Ignored** (no run, no seed): `**/*.md`, `refs/**`, `website/**`, `docs/**`, every workflow EXCEPT `main.yml` and the dispatch-only `webview2-probe.yml`, `.github/prebuild-toolchain/**`, `scripts/manifest-conformance/**`, `status/**` + `scripts/generate-status.mjs` (authored status data, ADR 0016 — `audit-runtimes.yml` runs the `status-data` rule over it on every PR, `main.yml` never opens it), `.githooks/**`, `flatpak/**`, `packages/node-gi/**` + `packages/napi/**` (own CI — without the carve-out their files map to no workspace and force a conservative full run), `LICENSE*`, `.gitignore`, top-level `STATUS|CHANGELOG|AGENTS|CLAUDE|README.md`. **Not everything in `main.yml` reads this table.** The `tree-checks` job (`gjsify lint`, `format --check`, `upgrade --check`) is deliberately outside the classifier: those are claims about the CHECKOUT, not about a set of workspaces, so gating them on `skip-all` made them true only for the paths a PR happened to touch — see [lint-format.md](lint-format.md) for the incident. **Precedence: IGNORE wins over GLOBAL_TRIGGERS** — ignored files are dropped FIRST, so `packages/infra/cli/README.md` does not force a full run; a docs-only PR is `skip-all` even when it edits infra READMEs. When adding a workflow or top-level dir the classifier doesn't know, update `affected.ts`'s tables + spec — silent mis-categorisation is the most common way to leak slowdowns back into the PR loop.

**IGNORE is scoped to `main.yml`, not to the repo** — the classifier is booted only by `main.yml`'s `changes` job and only `main.yml` reads its outputs, so "ignored" means "cannot change what `main.yml` builds or tests", never "unimportant". Reading it as a global claim is how the table stays under-filled: half of it has always been this kind of entry (`packages/node-gi/**`, `packages/napi/**` are load-bearing inputs to their OWN workflows), so the `OTHER_WORKFLOW_INPUTS` sub-table groups them and each entry NAMES the workflow that does gate it. **Membership is a two-part claim and both halves must hold: `main.yml` must not read the path, and some other workflow must.** Scoping is per-PATH, not per-name — `main.yml` DOES run manifest-conformance code, but reaches it by importing the `packages/infra/manifest-conformance/lib/**` WORKSPACE (which must keep seeding normally); only the `scripts/`-side repo-scoped half is ignored. Four directories had leaked into a conservative full run before the contract was written down.

**SCRIPT_COUPLINGS — a build input with NO manifest edge to follow.** The closure walk's only edges are `dependencies`/`optionalDependencies`, so when directory A is a real build input to workspace B because **B's build SCRIPT reads it** (`node scripts/…`, a `cpSync`, a repo-wide glob) no walk reaches B and the coupling must be DECLARED in `affected.ts`'s `SCRIPT_COUPLINGS`. **This one is silent in the WORSE direction**: an unmodelled path lands in `unmatched` and at least fails towards a full run, while this looks perfectly healthy — the input's own workspace seeds, a small green closure is reported, B is never rebuilt, and B's build-output cache keeps serving the copy it made before the change. The seed-bearing entry (`templates/**` → `@gjsify/create-app` + force `run-e2e`) is the measured case: `templates/*` ARE workspaces, so a template change always seeded its own `@gjsify/template-<name>` and looked handled, while the real consumer is unreachable twice over — it lives at `packages/infra/create-gjsify/` (a directory-name search misses it) and inlines templates into the build-cache candidate `dist-templates/` via `node scripts/process-template.mjs`. #853 passed only by accident of also touching root `package.json`. `why` is mandatory and names the script; a declared seed that is not a workspace fails LOUDLY to a full run naming itself (degrading quietly would restore the exact invisible no-rebuild the table prevents). **A coupling's payload can also be the TIER alone, with no seed** — `.githooks/**` and `packages/framework/react-native/**` are both workspaces-or-nothing whose guard is an e2e suite, so what they need turned on is `run-e2e`, not a rebuild. That half had a hole: the test-only shortcut (which skips closure expansion because test code has no downstream consumers) returned `runE2E: touchedE2E` and dropped `couplingRunE2E`, so a coupling's reach depended on the SHAPE of the changed path — `.githooks/pre-commit` survived only because a hook is not a spec file, while `packages/framework/react-native/src/*.spec.ts` fell through and turned the tier back off. Measured by the vector that exposed it, which was RED when written (#1550). **Three more couplings used to be safe only by accident** — `stage-prebuild.mjs` → 11 native packages, `check-refs-pin.mjs` → the 3 Rust bridges, `bootstrap-native-facades.mjs` → the infra facades — because a `scripts/` change landed in `unmatched`. They are now reached through their real readers (next paragraph): the native packages' `package.json` seeds them, root `build:infra` and the e2e suites force the full run. Carving `scripts/` (or a subtree) into IGNORE is still wrong: IGNORE drops a file BEFORE the readers lookup sees it, which would turn those three straight back into the silent stale-artifact failure.

**Root scripts → their readers (`affected-script-refs.ts`).** `scripts/` belongs to no workspace, so every script change used to force a full run: 33 of the 60 PRs before #1774 went full for that alone, most of them editing a website or gallery gate only `audit-runtimes.yml` runs. The classifier now replaces a changed root script by the tracked files that NAME it (file name, `.d.mts`↔`.mjs`, comment lines dropped), recursively through scripts that name scripts, and classifies those: a spec importing it seeds its workspace, a sibling workflow is IGNOREd, `tests/e2e/**` or `.github/actions/**` or anything unmodelled still forces the full run, and a script `audit-runtimes.mjs` names fires that GLOBAL_TRIGGER. Two readers are narrowed: `main.yml` counts only from a job that transitively `needs: changes` (`tree-checks` runs regardless, so its scripts cannot be skipped by this), and the root `package.json` only from `install`/`prepare`/`build`/`test` entries or an entry another root script or a gated job runs — not the `check:*` conveniences. The match is deliberately loose (an error message naming a script counts), because it may only be wrong towards running more. Not seen: a file name built at run time, and a tool walking `scripts/` as a directory (the ones that exist run outside `main.yml`'s gated jobs). Replayed over those 60 PRs: full runs 41 → 27, skip-all 5 → 11. The lookup reads `git ls-files`; if git cannot list the tree it is skipped and a root script is `unmatched` again.

**`include-args` transport — UNQUOTED tokens; zero matches are FATAL.** The classifier emits a space-separated list of already-shell-safe tokens consumed by an UNQUOTED `$INCLUDE_ARGS` expansion (spliced through `su … sh -c` nesting; expansions are never re-scanned for quoting). When `affected` once emitted `--include '@gjsify/fs'`, the apostrophes stayed IN the globs, every pattern matched zero workspaces, `gjsify foreach` exited 0, and **every selective PR built nothing in 0.65 s** while later steps inspected the cache-restored tree. Pre-quoting for unknown nesting cannot work; emitting tokens needing no quoting can (`assertShellSafeWorkspaceName`; unsafe name → non-zero → full run). **The silence was the real defect**: `gjsify foreach` now FAILS when an `--include` PATTERN matches zero workspaces — scoped to the pattern, not the final selection (`--shard`/`--exclude`/script-presence legitimately narrow to empty). No opt-out flag: an escape hatch would re-arm the silence.

**Kill switch**: repo/org variable `GJSIFY_CI_FORCE_FULL=1` short-circuits the classifier. Heavy hammer — disables ALL selective gates; set only to debug a suspected mis-gate, then unset.
